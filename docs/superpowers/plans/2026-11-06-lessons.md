# Lessons Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Implementer subagents run on model `sonnet` (user preference).

**Goal:** A teacher posts a deck's narrated video to a class as a *lesson*; students watch it on their own time, the video stops at quiz checkpoints (server-enforced), each answer shows ✓/✗, progress resumes, and the final score is an ordinary quiz attempt in class stats.

**Architecture:** A lesson is a `quiz_classes` posting with `mode = 'lesson'` (migration 0018). The video record gains per-slide timings; checkpoint order is computed identically in TS (`src/lesson/checkpoints.ts`) and SQL (`lesson_stops`). Students reach the video through a new storage select policy and every answer goes through a security-definer RPC that checks order and a server-side `watched_until` that grows no faster than real time.

**Tech Stack:** React 19 + TypeScript (`verbatimModuleSyntax`, `erasableSyntaxOnly`), Vitest (no jsdom; SSR render tests via `react-dom/server`), Supabase Postgres (plpgsql, RLS) + Storage.

**Spec:** `docs/superpowers/specs/2026-11-06-lessons-design.md`

## Global Constraints

- No AI/provider call anywhere in this feature.
- Students never receive an answer key: no RPC returns `quiz_questions.answer`; `lesson_answers` stores only `correct`.
- Migration 0018 must **not** gate classroom reads: lesson modes are read in a separate best-effort query; without 0018 every posting is a quiz.
- RLS policies never select another RLS table directly; cross-table checks go in `security definer stable` functions (0012 rule).
- Every new RPC: `revoke execute ... from public, anon; grant execute ... to authenticated`. Internal helpers: revoked from `authenticated` too.
- Heartbeat cadence 5 s while playing; per-beat advance cap 15 s; slack 2 s; answer tolerance 1 s; playback rate fixed at 1×.
- User copy: "Make the narrated video first." / "Make the video again to use it in a lesson." / "Watch up to this question first." / "Answer the questions in order." / "The video for this lesson was removed." / "This quiz is a lesson in <class>." Status labels "Start lesson" / "Continue lesson" / "Finished · <score>%".
- `mediabunny` and `html-to-image` stay out of the entry bundle; the lesson player imports nothing from `src/video/` except `videoRecord.ts` types.
- Follow `src/quiz/api.ts` conventions: components never build queries; RPC refusals rethrown as bare `Error`s with the SQL's sentence.

## Review Focus

1. **`timeupdate` overshoots a stop** (fires every ~250 ms): the player must still stop at the first unanswered stop whose time has passed, not skip it — `dueStop` test in Task 3.
2. **Several questions on one slide, or on the last slide where the video `ended` fires before `currentTime` reaches the stop** — asked in order, one after another; `ended` makes every remaining stop due — Task 3 tests.
3. **Question whose card was deleted / not in the video** — asked at the end, after the last slide's questions, in TS and SQL identically — Task 2 test + Task 5 SQL check on the same fixture.
4. **Project without 0018** — classroom pages load, lesson modes read as none — Task 6 `lessonModesFrom` test.
5. **Heartbeat lag or failure** — the progress bar trusts only the server's `watchedUntil`; an answer refused with "Watch up to this question first." rewinds to it and keeps playing — Task 3 reducer test (`refused` event).
