# PPTX Fit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Export text that already fits its boxes (measured in the browser, sized to a capped ladder, laid out from measured heights), so the .pptx looks right in PowerPoint, Google Slides, Canva and Keynote.

**Architecture:** A pure `export/textFit.ts` (wrap, fit, ladder, insets) takes a `TextMeasurer`. The browser's canvas measurer is built once in `exportDeckToPptx` and threaded to every renderer as a fifth parameter. Renderers stop using fixed heights and `pointSize` directly: they fit each box and position the next from the previous one's measured height.

**Tech Stack:** TypeScript 6 strict, pptxgenjs (dynamic import in `pptx.ts` only), Vitest (node env), browser Canvas 2D.

**Spec:** `docs/superpowers/specs/2026-09-19-pptx-fit-design.md` (binding).

## Global Constraints

- `src/export/` stays React-free. `export/measureText.ts` is the only new file allowed to touch `document` and canvas, and it must degrade to `estimateMeasurer` when either is missing. Everything else in `src/export/` stays pure.
- No word is ever dropped. The "every word arrives" tests in `slideRenderers.test.ts` must keep passing unchanged.
- `WIDTH_HEADROOM = 1.1`, `HEIGHT_HEADROOM = 1.1`, `FLOOR_PT = 10`, default `lineSpacing = 1.2`.
- Text box inset on every text box: pptxgenjs `margin` is in **points**, ordered `[top, right, bottom, left]`. Use `TEXT_MARGIN_PT = [3.6, 7.2, 3.6, 7.2]` (0.05 in / 0.1 in), and subtract the same inches in the fit maths.
- Size ladder (pt) `{cap, min}`: title `{44, 28}`, heading `{30, 20}`, subheading `{22, 16}`, body `{18, 12}`, statSingle `{54, 28}`, statGrid `{40, 24}`. Preferred = `Math.min(cap, pointSize(rem, fontScale))`.
- Slide is 10 × 5.625 in. Every box must lie within it.
- Keep `fit: 'shrink'` on text boxes as a PowerPoint backstop.
- Type-check with `npx tsc -b; echo "EXIT=$?"`. The output is ANSI-coloured, so trust the exit code. Lint baseline is 10 warnings; add none. Run `npx vitest run`.
- Commit messages end with a blank line then `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
- Implementation subagents run on Sonnet (user requirement).

### Task 1: `export/textFit.ts`, the pure fitting core

**Files:**
- Create: `src/export/textFit.ts`
- Create: `src/export/textFit.test.ts`

**Interfaces. Produces:**
```ts
export interface FontSpec { face: string; sizePt: number; bold: boolean; italic: boolean }
/** Width of `text` set in `font`, in inches. */
export type TextMeasurer = (text: string, font: FontSpec) => number
export const WIDTH_HEADROOM = 1.1
export const HEIGHT_HEADROOM = 1.1
export const FLOOR_PT = 10
export const DEFAULT_LINE_SPACING = 1.2
export const TEXT_MARGIN_PT: [number, number, number, number] = [3.6, 7.2, 3.6, 7.2]
export const INSET_X_IN: number   // (7.2 + 7.2) / 72  — total horizontal inset
export const INSET_Y_IN: number   // (3.6 + 3.6) / 72  — total vertical inset
export type SizeRole = 'title' | 'heading' | 'subheading' | 'body' | 'statSingle' | 'statGrid'
export const SIZE_LADDER: Record<SizeRole, { cap: number; min: number }>
/** min(cap, pointSize(rem, fontScale)), never below the role's min. */
export function preferredSize(role: SizeRole, rem: number, fontScale: number | undefined): number
/** Deterministic, DOM-free: chars × em-factor × sizePt/72. em-factor 0.55 regular, 0.6 bold; uppercase letters and digits count 0.65/0.7. */
export const estimateMeasurer: TextMeasurer
export interface FitParagraph { text: string; bold?: boolean; indentIn?: number }
export interface FitSizing { preferredPt: number; minPt: number; face: string; bold?: boolean; italic?: boolean; lineSpacing?: number }
/** Lines `text` wraps to at `widthIn` (explicit '\n' honoured; a word longer than the line is broken by characters). Uses WIDTH_HEADROOM. */
export function wrapLines(text: string, widthIn: number, font: FontSpec, measure: TextMeasurer): string[]
/** Height in inches the paragraphs need at sizePt inside a box of `boxWidthIn` (insets and HEIGHT_HEADROOM included). */
export function textHeight(paragraphs: FitParagraph[], boxWidthIn: number, sizing: FitSizing, sizePt: number, measure: TextMeasurer): number
/** Largest size from preferredPt down (1pt steps) whose textHeight ≤ maxHeightIn; continues below minPt to FLOOR_PT only if needed; never below FLOOR_PT. */
export function fitText(paragraphs: FitParagraph[], box: { widthIn: number; maxHeightIn: number }, sizing: FitSizing, measure: TextMeasurer): { sizePt: number; heightIn: number }
```
- `pointSize` is imported from `./textRun` (existing: theme rem × fontScale × `PT_PER_REM`, rounded).
- A paragraph's usable width is `boxWidthIn - INSET_X_IN - (indentIn ?? 0)`. Height = Σ over paragraphs of (lines × sizePt × lineSpacing / 72), then × HEIGHT_HEADROOM, + INSET_Y_IN. An empty paragraph list is height `INSET_Y_IN`. An empty string still counts as one line.
- `bold` on a paragraph overrides `sizing.bold` for that paragraph's measurement.

- [ ] **Step 1: Write `textFit.test.ts` first.** Use a fake measurer where each character is exactly 0.1 in at 10pt, scaling linearly with size: `(t, f) => t.length * 0.1 * f.sizePt / 10`. Cover:
  - `wrapLines`: fits on one line; wraps at the word boundary; honours `'\n'`; breaks a word longer than the line; applies WIDTH_HEADROOM (a string exactly the line width without headroom wraps with it).
  - `textHeight`: one line at 18pt with spacing 1.2 = (18 × 1.2 / 72) × 1.1 + INSET_Y_IN; indents narrow the width.
  - `fitText`: returns `preferredPt` when it fits; steps down to the first size that fits; goes below `minPt` when nothing fits at `minPt`; never below `FLOOR_PT` (returns FLOOR_PT with its real, possibly over-budget height).
  - `preferredSize`: `('heading', 1.875, undefined)` → 30 (34 capped); `('body', 1, undefined)` → 18; `('body', 1, 0.5)` → 12 (9 raised to the role min); `('title', 2.5, 1)` → 44 (45 capped).
  - `estimateMeasurer`: deterministic; bold is wider than regular; widths scale linearly with size.
- [ ] **Step 2:** Run it and see it fail (module missing). **Step 3:** Implement. **Step 4:** Run `npx vitest run src/export/textFit.test.ts`, then the full suite; tsc EXIT=0; lint at baseline. **Step 5:** Commit.

### Task 3: title, body and heading arrangements fitted and flowed, plus the fit harness

**Files:**
- Modify: `src/export/slideRenderers.ts` (`addHeading`, `renderTitle`, `renderBody`)
- Modify: `src/export/slideRenderers.test.ts` (add the fit harness)

**Interfaces. Consumes:** Task 1 (`fitText`, `textHeight`, `preferredSize`, `TEXT_MARGIN_PT`, `estimateMeasurer`), Task 2 (`measure` parameter). **Produces:** `addHeading(...)` now returns the y (in inches) where content may start, so Task 4 can place content under the real heading.

Layout constants (add near `MARGIN`): `TOP = 0.45`, `BOTTOM = SLIDE_H - 0.45`, `HEADING_MAX_H = 1.5`, `RULE_GAP = 0.08`, `RULE_H = 0.045`, `CONTENT_GAP = 0.22`.

- **`addHeading(slide, card, theme, style, measure): number`**
  - Fit the heading with role `heading` (face = heading face, bold as today) into `{ widthIn: CONTENT_W, maxHeightIn: HEADING_MAX_H }`.
  - Box at `y = TOP`, `h = fitted height`, `valign: 'top'`, `margin: TEXT_MARGIN_PT`, `fontSize: fitted`, `fit: 'shrink'`.
  - The accent rule goes at `y = TOP + h + RULE_GAP`.
  - Return `TOP + h + RULE_GAP + RULE_H + CONTENT_GAP`.
- **`renderBody`**
  - Content area from `addHeading`'s return value to `BOTTOM`.
  - Fit the flattened lines as paragraphs (bullet lines `indentIn: 0.3`; comparison items at `indentLevel` 1 get `indentIn: 0.6`) with role `body`, `lineSpacing: theme.typography.lineHeight`.
  - The box spans the whole area, with `valign: 'middle'` and the fitted `fontSize`.
- **`renderTitle`**
  - Fit the title with role `title` into `{ widthIn: CONTENT_W, maxHeightIn: 2.4 }`.
  - If there are paragraphs, fit the subtitle with role `subheading` into `{ widthIn: CONTENT_W - 1.6, maxHeightIn: BOTTOM - TOP - titleH - 0.25 }`.
  - The group height is `titleH (+ 0.25 + subH)`, starting at `y = (SLIDE_H - groupH) / 2`.
  - Each box is exactly its fitted height, with `valign: 'top'` and `margin: TEXT_MARGIN_PT`.
- Every text box in these three gets `margin: TEXT_MARGIN_PT`.

**Fit harness in `slideRenderers.test.ts`** (reused by Tasks 4 and 5):
- A helper `expectFits(slide)`: for each captured text box, rebuild its paragraphs from the captured runs (split at runs whose options have `breakLine`; bullet runs count as indent 0.3 in; `indentLevel` 1 as 0.6 in).
- It recomputes `textHeight` at the box's own `fontSize` with `estimateMeasurer`, the box's `fontFace`, `bold` and `lineSpacingMultiple` (default 1.2).
- It asserts the recomputed height ≤ `h + 1e-6`, and that `x ≥ 0`, `y ≥ 0`, `x + w ≤ 10 + 1e-6`, `y + h ≤ 5.625 + 1e-6`.
- Fixtures:
  - a **long heading** of 20 words;
  - a **long body** of 8 bullets of 14 words each;
  - a **title card** with a 16-word title and a 45-word subtitle.
- Tests: the title and body arrangements with the long fixtures pass `expectFits`. The body box has `valign: 'middle'`. A short heading (3 words) gets a heading `fontSize` of 30 for DEFAULT_THEME (the cap). The accent rule's y is greater than the heading box's `y + h`.

- [ ] **Step 1:** Write the harness and tests first. They fail against the fixed-height code, since the long heading overflows 0.9 in.

### Task 4: stat, two-column and quote arrangements

**Files:**
- Modify: `src/export/slideRenderers.ts` (`renderStat`, `renderTwoCol`, `renderQuote`)
- Modify: `src/export/slideRenderers.test.ts`

**Consumes:** Task 3's `addHeading` return value and the fit harness; Task 1's API.

- **`renderStat`**
  - Area from `addHeading`'s return value to `BOTTOM`.
  - Paragraphs, when present, are fitted first with role `body` into `{ CONTENT_W, maxHeightIn: 1.2 }` and placed at the bottom of the area; the stat grid gets the rest (minus a 0.15 in gap).
  - Per cell: fit the value with role `statSingle` (1 stat) or `statGrid` (several) into `{ cellW, cellH * 0.62 }`, and the label with role `body` into `{ cellW, cellH * 0.34 }`.
  - Unify sizes across the grid: every value box uses the smallest fitted value size, and every label the smallest label size, so the numbers line up.
  - Keep `valign` bottom for the value and top for the label; `margin: TEXT_MARGIN_PT`.
- **`renderTwoCol`**
  - Columns start at `addHeading`'s return value.
  - Each column heading is fitted with role `subheading` into `{ colW, 0.8 }`, using the shared smallest size. All heading boxes get the tallest fitted heading height, so the bullets start at one y.
  - Bullets are fitted with role `body` into `{ colW, BOTTOM - bulletsTop }`, using the shared smallest size across columns.
  - The fallback to `renderBody` is unchanged (pass `measure` through).
- **`renderQuote`**
  - The quote is fitted with role `subheading` into `{ CONTENT_W - 1.0, maxHeightIn: area - (attribution ? 0.6 : 0) }`.
  - The attribution is fitted with role `body` into `{ CONTENT_W - 1.0, 0.6 }`.
  - The pair is vertically centred in the area; each box is its fitted height.
- **Tests:**
  - `expectFits` for a single stat with a long label plus a 40-word paragraph;
  - a 6-stat grid;
  - a two-column card with 3 groups of 6 long items;
  - a quote of 60 words with an attribution;
  - grid value boxes all share one `fontSize`, and two-column bullet boxes all share one `fontSize`.
