## Testing

Vitest covers **only pure, high-value logic**, in `*.test.ts` files beside the module (layout classifier, theme tokens, brief drafts, retry/fallback/providers against mocked `fetch`, generation pipeline + validation, export fit/renderers, editor geometry/marks/removal, classroom stats/roles). Look next to the code you change; add a colocated test for new pure logic, and mutation-check safety rules (e.g. which failures fail over).

- Component tests are deliberate exceptions, for JSX-only failures no pure test can see: `components/layouts/everyBlockRenders.test.tsx` and a smaller render smoke test, `components/editor/ToolsPanel.test.tsx` (which sections appear for which selection, their order, zoom in the header, Remove fill only with a fill, no Add item button in the panel). `everyBlockRenders`: SSR of every layout (forced + automatic, both visual treatments) against a card holding every block type, asserting each block's text appears exactly once. It guards layouts silently dropping blocks. **A new layout or block type must be added to it.**
- No jsdom. The live editing DOM (`EditableText`, selection overlay, zoom, pan, drag) is untested in a browser; only its pure arithmetic is.
- RLS/SQL rules are checked by hand: `supabase/tests/0009_classroom_rls.sql`, `supabase/tests/0010_account_type_lock.sql`.

## Environment

- `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` (see `.env.example`). If absent, `supabaseConfigured` (`src/lib/supabaseClient.ts`) is `false`, store methods no-op, and `/login` shows an explanatory message instead of a form — nobody can log in, so the app is effectively unusable.
- `VITE_ANTHROPIC_API_KEY` (one chain link, first), `VITE_GROQ_API_KEY` (two chain links) and `VITE_GEMINI_API_KEY` (one), built into `PROVIDER_CHAIN` in `fallbackProvider.ts` (imported by `CreatePage.tsx` and the narration page) and **baked into the client bundle** — fine for local/personal use, readable by anyone who can load a deployed build. Any may be omitted (its provider drops out of the chain) but at least one is required; `/new` checks on mount. No in-app key entry, no server proxy, by design. **Unlike Groq/Gemini's free tiers, the Anthropic key is billed per token** — a deployed build isn't just readable, it's spendable; see `.env.example`.
- Accounts are required: every route except `/login` and `/reset-password` is under `<RequireAuth>`. No guest mode. `store/authStore.ts` = Supabase email/password with email confirmation. `ensureSession()` only waits for hydration.

## Core rule: generate once

A deck's cards come from **one** AI call at creation and nothing afterwards asks the model for card content again. To get different content, start a new project. The user can still edit by hand (text in place, delete/reorder cards, nudge elements, add a slide, change slide type, add list items, remove elements) — none of that calls a provider. Research and repair happen *before* the deck exists, inside `generatePresentation`. Narration (`generateNarration`) is a separate field never rendered on slides or exported to PPTX — it is **not** precedent for a "regenerate this slide" button. Neither is a **quiz** (see Quizzes): a separate artifact generated from a deck on demand, it never touches `cards` and is no reason to let the model rewrite slides after creation.

Authority: the AI decides what a card says and which blocks it holds; the layout engine decides how it renders. Element nudges are *deltas* on top of the layout, never a replacement. There is deliberately no free-form canvas.

## Creation flow

1. `pages/CreatePage.tsx` is a chat-style intake: topic → slide count (number or "let AI decide" = `'auto'`) → audience (General/Students presets or free text; `audience` stays a free string downstream) → detail level → optional guidance. Answers are editable after the fact (`editing: StepKey | null`, locked while a request is in flight) and persisted as a draft on every keystroke (see Brief drafts), deleted once a deck is created.
   - **Tone is removed from the intake, not from generation**: `DEFAULT_TONE` (`'professional'`, `ai/prompts.ts`) is still sent. Restoring it = `STEP_ORDER` + an `Answers` field + the card. It had to leave `STEP_ORDER` because the active question is the first *unanswered* step; an unanswerable step stalls every brief.
   - Slide count (`lib/slideCount.ts`): `MAX_SLIDES = 7` (tightened from 10, deliberately "for now" — see its doc comment), `DEFAULT_SLIDE_COUNT = 5`, floor 1 (only the ceiling is enforced). **Raising `MAX_SLIDES` requires revisiting the Groq deck token budget and the narration budget** (below); past ~20 slides narration cannot complete.
   - `guidance` is injected into the user prompt as a hard constraint overriding the system prompt.
2. On the last answer it calls `generatePresentation` (`src/generation/pipeline.ts`), owning an `AbortController` (aborted on unmount; `signal.aborted` returns to the brief, not an error). **Every provider must honour the signal in both `fetch` and backoff `sleep`** — the leave-mid-generation prompt promises cancel stops the request.
3. Output is validated against `generatedDeckSchema` (`generation/schemas.ts`, re-exported from `ai/provider.ts`). Enums (`plan.purpose`, `visualType`, `layoutFamily`, a claim's `type`) use zod `.catch(default)` so an off-list value never costs a deck; `plan`, `speakerNotes` and required shape still fail; each card's first block must be a `heading`. One retry is sent with the exact zod errors.
4. `store/presentationStore.ts` `createDeckFromGeneration(deck, requestedCount, result)` atomically creates the `presentations` + `cards` rows, prefills each card's `narration` from `speakerNotes` (`{text, generated}` both the same string; blank note → unset), writes `presentations.generation` best-effort in a separate try/catch (a project lacking migration 0011 just warns), then navigates to `/deck/:id`.
5. `engine/emphasis.ts` `applyEmphasis` converts `*x*`/`**x**` into a **bold** mark in `card.inline` under the editor's `textRef`, stripping delimiters (marks are character offsets, so stripping at render time would desync). It runs at ingest **and** at the read boundary (`cardFromRow`) to convert older decks; hence it must be idempotent — a run that already carries marks is skipped entirely, delimiters included. The regex needs non-space run edges and no inner asterisk (keeps `2 * 3` alone).

"Skip and start blank" (`createDeck`) makes an empty project with no AI call.

### Blueprints (`ai/slideBlueprints.ts`)

Three (Informing & Training, Persuading & Selling, Storytelling & Engaging), each a 10-slide master sequence with the design doc's 5–10 scaling tables held verbatim (below 5, `sequenceFor` compresses the 5 column keeping opening and close). **The model picks the blueprint**, so the prompt carries all three candidate sequences (every column for `'auto'`). The sequence is **guidance, not rails**: merge/replace rows allowed, skip agenda-style rows unless formal; the slide count is still exact. `role` on a card is optional. `sequenceMismatch` only runs if some card has a `role`, and only warns (nothing can be regenerated, so a near-miss must not cost the deck). At ingest `roleLayoutHint` turns a role into an explicit layout where blocks support it (lets story `insight`/`closing-line` be heroes, since `chooseLayout` awards `hero` only to the first card); the role is then discarded (not stored).

### Token budgets (per provider, not shared)

- Groq `deckMaxTokens` (`ai/prompts.ts`): `clamp(n*480 + 2600, 5200, 7000)`, 7000 for `'auto'` — tuned to Groq's 8,000 TPM free tier, which counts *requested* output. The 5200 floor clears `gpt-oss-120b`'s ~3,400 reasoning tokens. Accepted risk: a 10-slide deck can truncate → fails shape check → one retry → error.
- Gemini `geminiDeckMaxTokens`: `clamp(n*700 + 3000, 6000, 12000)`, 12000 for `'auto'`.

## Generation pipeline (`src/generation/`)

`generatePresentation(provider, topic, brief, options)` → `{ deck, evidence, research, claims, flags, repaired }`. Stages: research → plan+write → validate → repair → re-validate. Design: `docs/superpowers/specs/2026-09-19-content-generation-pipeline-design.md`.

- **One plan+write call, not planner/writer/reviewer**: the writer is a reasoning model spending ~3,400 tokens thinking per call against an ~8,000 TPM window, so separate calls would trip the limit and triple the wait. Each card's `plan` (purpose, audienceQuestion, keyMessage, visualType, layoutFamily, transition, importance) is emitted in the same JSON *before* its `blocks`. `plan.layoutFamily` is no longer requested (nothing reads it; schema still accepts it).
- **Research is best effort and must never cost a deck.** One `provider.research(topic, brief, today, signal)` call returns `{sources, findings, disagreements}` as JSON in free text (JSON mode can't combine with a tool call). Any non-cancel failure → `evidence: null, research: 'failed'`. Skipped (`'skipped'`) when `ai/researchPrompt.ts` `isUserMaterialOnly(guidance)` matches phrases like "only use the/my/these facts" (a bare "only use" is deliberately *not* enough). Research/repair pass `maxRetries: 0` (a 429 right after a deck call meets a saturated window anyway); deck/narration keep the full retry policy. Research `maxTokens` is 4000 (2000 let a reasoning model exhaust the budget before writing the JSON). Gemini grounding is implemented to the documented API but **untested live**.
- `parseEvidencePack` is lenient about the wrapper (strips `【…】`, `extractJsonObject`), strict about content: drops sources with neither `url` nor `publisher`, drops findings whose surviving `sourceIds` are empty, returns `null` if no finding survives.
- **The model never writes a source object — only cites ids.** The pipeline attaches the pack's own `Source` records. `Claim.id` (`c${slide+1}-${n+1}`) and `Claim.verified` are computed by `verifyClaims` (`validation/evidence.ts`); `verified` needs ≥1 sourceId, all present in the pack, always false with a `null` pack.
- **Validation** (`validateDeck`) runs 17 pure rules split across `validation/structure.ts` and `validation/evidence.ts`, each yielding a `QualityFlag {type, severity, slideIndex?, message, suggestedAction}`. **Severities are deliberately conservative** — a false "high" buys an unneeded repair call, so an unsure rule reports `low` (logged, never repaired). `UNSUPPORTED_STATISTIC`/`MISSING_SOURCE` are `low` when there's no pack at all (no-evidence behavior is documented prompt behavior, not a defect); otherwise `high`/`medium` by pack strength.
- **List dominance is fixed in what the model writes, not the classifier** (`chooseLayout` draws every single `bulletList` as iconGrid/numberedList): the prompt's VISUAL CHOICE section binds `plan.visualType` to required blocks and caps bullet slides at ~40% (none adjacent). `LIST_DOMINANT` and `VISUAL_MISMATCH` (medium) are in `REPAIRABLE`. Chart visual types are deliberately not checked against `stat` blocks (would push the writer to invent numbers).
- **Repair fires at most once.** `repairTargets(flags)` picks slides with a high flag or a medium `REPAIRABLE` flag, ranks by (highs, mediums) desc, ties by index, caps at `MAX_REPAIR_SLIDES` (4). `applyRepairs` (`generation/repair.ts`) writes only to targeted, in-range, schema-valid slides; never changes deck length or mutates input; untouched cards keep object identity; a replacement omitting `role` keeps the original's (else story heroes silently vanish). Repair failure (non-cancel) keeps the unrepaired deck. After a landed repair the deck is re-validated and returned `claims`/`flags` are post-repair.
- **Ingest:** `speakerNotes` become `narration` **exactly as written — no citations appended** (a cloned voice reads it aloud). No on-slide citations and no references slide (each needs a block the renderer/export/editor understand; a references slide would also silently grow the slide count). `buildGenerationMeta` (`generation/meta.ts`) writes brief, sources, plans/claims re-keyed by **card id**, flags, research to `presentations.generation`; nothing reads it yet.

## AI providers (`src/ai/`)

`AIProvider`: `generateDeck`, `research`, `repairSlides`, `generateNarration`. All take an optional `AbortSignal`.

### Retry (`ai/retry.ts`, shared by `callGroq` and `callGemini`)

Retries `RETRYABLE_STATUS` (429/503) up to `maxRetries` (default `MAX_RETRIES` = 3). `backoffDelayMs` is pure: exponential 1s/2s/4s; a server `Retry-After` (seconds or HTTP-date; past date → 0) wins **only if longer**; clamped to `MAX_DELAY_MS` (20s) so a 60s TPM window doesn't read as a hang. `sleep()` is abortable — cancel must not wait out a timer.

### Fallback (`ai/fallbackProvider.ts`)

`FallbackProvider` implements `AIProvider` over an ordered chain built once in `fallbackProvider.ts` (`PROVIDER_CHAIN`), imported by both `CreatePage` and the narration page; all four methods go through one private `run<T>(label, call, signal)` failover loop. Chain: `AnthropicProvider` → `GroqProvider` on `openai/gpt-oss-120b` (research on `openai/gpt-oss-20b` with `browser_search`) → second `GroqProvider` on `groq/compound` (deck/repair/narration only) → `GeminiProvider` (`gemini-flash-latest`). `GroqProvider` takes `GroqModelOptions` (`deckModel`, `researchModel`, `researchTools`, `supportsResearch`).

- **Only `capacity` failures (429/503/413) hand off.** `AIProviderError` carries `kind` (`capacity|auth|request|response|unknown`) + status via `kindForStatus`. An `auth` failover would hide a mistyped key behind Gemini; `request`/`response` fail identically on the backup. This is load-bearing and mutation-tested.
- **Cancellation never hands off** (aborted signal or bare `AbortError`), or the deck the user walked away from still arrives.
- The compound link's `supportsResearch: false` makes `research()` throw `capacity` before any network call: `groq/compound-mini` returns 413 for any prompt whose built-in search runs, at every token budget. `capacity` makes the chain skip straight to Gemini.
- `groq/compound` ignores `response_format` and wraps replies (`**…**\n```json\n{…}`); `ai/jsonText.ts` `extractJsonObject` (first `{` to last `}`) is used by every JSON parser. JSON mode is still requested everywhere.
- A provider with a missing key is left **out** of the chain; `AnthropicProvider` is included only when `VITE_ANTHROPIC_API_KEY` is present, same pattern as the other two; dropping `VITE_GROQ_API_KEY` drops both Groq links → Anthropic-then-Gemini with no code change.
- **Research now runs through Claude's paid web search by default**, not Groq's free `browser_search` link, because Anthropic leads the chain for all four methods. This is a deliberate cost tradeoff (the user chose Claude end-to-end over the cheaper Groq-first-research default) — do not "fix" it back to research-only-on-Groq.

## Brief drafts (`src/lib/briefDrafts.ts`)

Unfinished briefs are drafts at `/drafts` (`DraftsPage`, sidebar badge). All reads/writes go through this file, so moving to Supabase later means rewriting only it.

- Storage is browser `localStorage` (`lekturac:brief-drafts:<uid>`), not Supabase; writes are try/catch'd (blocked storage → silently unsaved). Drafts don't follow the user across devices.
- **The key is namespaced by user id — load-bearing**: `signOut()` clears only the Supabase session, so a shared key would hand your briefs to the next account. `storageKey()` returns `null` while the session hydrates and reads/writes skip — never fall back to an un-namespaced key. The cache remembers its key and `useAuthStore.subscribe` invalidates on user change.
- `purgeForeignDrafts()` runs on sign-**in**, never sign-out (sign-out would destroy your own unfinished briefs; no server copy). Order in that subscription is load-bearing: drop cache → `listDrafts()` (lets `drainLegacyKeys()` adopt `lekturac:create-draft` and un-namespaced `lekturac:brief-drafts` into the current user) → purge. Purging first deletes the legacy list before migration. Purge collects keys before removing (removal reindexes).
- `BriefDraft` carries `pendingText` (text typed into the open question, restored into the first-unanswered step). `saveDraft` drops a draft with no answers and no pending text. `MAX_DRAFTS = 30` drops oldest; nothing expires on a timer.
- `useDrafts()` is `useSyncExternalStore`; `listDrafts()` caches its sorted array and rebuilds only on mutation/`storage` event — an unstable snapshot re-renders forever.
- Leaving `/new` mid-brief is free; only leaving mid-*generation* prompts. Resume is `/new?draft=<id>`, resolved once into a ref. Drafts are deliberately not decks (own `DraftRow`, not in `selectDecks`).

## Content model & layout engine (`src/engine/`)

- `contentBlocks.ts`: `ContentBlock` zod union (`heading`, `paragraph`, `bulletList`, `stat`, `image`, `quote`, `timelineStep`, `comparisonGroup`) and `Card` (`id`, `orderIndex`, `blocks`, `layout`, `visualStyle`, `textStyle`, `inline`, `adjusts`, `narration`). `cardSchema` allows `blocks: []` (a blank card is real); the *generation* schema still requires a heading.
- `chooseLayout(blocks, {isFirstCard})` is a rule-based classifier (no LLM): `hero`, `statHero`, `statGrid`, `comparison`, `timeline`, `quote`, `iconGrid`, `numberedList`, `textFocus`, `gallery`, `standardSplit`, `standard`. `resolveLayout` defers to it when `card.layout === 'auto'` (nearly every card). Only two things name a layout: the Level 2 picker and a `title` card added anywhere but the front (needs explicit `hero`). `cardKindOf` lets a named layout outrank blocks when reporting a card's type.
- `card.visualStyle` (`'structured'|'expressive'`) is picked by the AI per card; `LayoutRenderer` passes it as each component's `variant`, and each component branches its own JSX. Legacy rows default to `'structured'` at the read boundary.
- **Families vs frames.** *Families* (`statGrid`, `timeline`, `comparison`, `iconGrid`, `numberedList`, `gallery` — `FLOW_LAYOUTS`) render through `FlowLayout`, which draws blocks in author order via `inferGroups` → leaves through `BlockRenderer`, runs of same-type blocks through `GroupRenderer` (`boxes`, `statRows`, `timeline`, `timelineRow`, `columns`, `table`, `chips`, `numbered`, `checklist`, `split`, `gallery`; exhaustive switch). *Frames* (`hero`, `statHero`, `quote`, `textFocus`, `standard`, `standardSplit`) keep their own components; `LAYOUT_COMPONENTS` is typed to exclude the family names. Heading size is uniformly `h2` (shared `Heading`) except opening `HeroLayout` (`h1`) — don't reintroduce per-layout variance.
- **Extra varieties are explicit choices only**: lists have `iconGrid|numberedList|checklist|splitList`, stats `statHero|statGrid|statList`, timelines `timeline|timelineRow`, comparisons `comparison|comparisonTable` (each in both visual styles). `layoutVarieties` lists them. **The classifier never awards the new ones**; the stored `layout` reaches the arrangement as `hint` to `inferGroups` (a hint for a different run type is ignored). The PPTX export maps them onto its five arrangements; no template in `cardTemplates.ts` uses them.
- **Grouping is derived at render, never stored; the invariant that makes it safe:** `inferGroups` never reorders, drops or duplicates a block and every block keeps its index (`groups.test.ts` checks exhaustively). A block's index is its `textRef`, `card.adjusts` key, `data-block-index` and editor selection, so grouping changes how a card looks and nothing else. Runs are **consecutive only**. A single bullet list is arranged `chips`/`numbered` by explicit layout, else the classifier's `iconGrid` rule (shared `MAX_CHIP_ITEMS`/`SHORT_ITEM_MAX_CHARS`). Hand-built groups would need stored groups (future work).
- **Frames must end with `<Leftovers blocks consumed />`** (`engine/blockPartition.ts` `leftoverBlocks`, total over any consumed list): each frame draws only the types it understands, so it names the indices it drew and leftovers keep their original index. A frame showing only the *first* of a type must name only that one. `StandardLayout` and families need none.
- Cards have **no fixed aspect ratio or height** — they size to content. Don't add `aspect-video` to the card container.
- `Enter` inside a run inserts a real `\n` (`insertTextAtCaret`); every run renders `white-space: pre-wrap` on live and read-only surfaces; a trailing newline gets `<br data-run-end>` purely so the caret has a box. Paste is plain text with CRLF normalised. Marks are character offsets, so this needed no other change.

### Editing model

- **Selection drills in**: a press on an unselected card selects the **card** (however precisely it hit an element); a second press takes the element (so card-scope formatting is reachable; the cost is one extra press before drag/resize handles). Then one press selects, a further press (or double-click) edits; Backspace/Delete removes only while not typing; Escape steps out item → list → card (the page's Escape handler stands down for a key already `preventDefault`ed). `EditableText` tells select-vs-edit presses apart by recording at pointer-down whether its element was already selected. Scope is read off the selection by `engine/textScope.ts` (element → card → deck; a character range only narrows marks and value marks, not whole-element font/size/align). `selectedBlockIndex` lives beside `selectedCardId` in `EditorPage`, written via one `apply(Selection)`. `Selection` carries `itemIndex`; an item is a refinement of its list (lit via `data-item-selected`; arrangements spread `useItemProps()` on item containers so a press there doesn't select the list). Items are not draggable/resizable. The card's accent ring (`CardCanvas` `showCardRing`) is drawn only while the card itself is the selection — once an element is picked its own selection box replaces it.
- **Undo/redo** (`past`/`future` in `presentationStore.ts`) snapshots the whole `cards` array (cap 50, reset on `loadDeck`, in-memory). It relies on `persistCardsSync(presentationId, previous, next)` diffing to delete dropped rows and upsert the rest (ids preserved, so undo of a delete re-inserts). Keys ⌘Z / ⌘⇧Z / ⌘Y in one `EditorPage` listener that ignores input/textarea targets **but not a live text run**: the browser's own undo stack only knows typing, so deferring to it made ⌘Z do nothing for a nudge, formatting or added element whenever a run was focused (which a highlighted element usually has). The store undoes everything; `EditableText` repaints a live run whose node text differs from the store's `value` (typing always leaves them equal, so a mismatch means undo/redo moved it), or the node would keep stale text and write it back on the next keystroke. `EditorPage` also drops a selection/edit that an undo left pointing past the end of the card.
- **Removal** (`engine/removeElement.ts`, pure): removing block N renumbers every later address — `textRef`, `adjusts` key, bare-index typography key in `inline`, runs, list-item keys — and drops the removed element's own. `blocks`/`inline`/`adjusts` are rewritten together and written **immediately** (`commitRemoval`) after dropping the card's pending `blockText:`/`inline:`/`adjusts:` saves (they captured old values and would put the element back). Keys that aren't addresses are kept. Removing the last element leaves a blank card (never deletes it; `LayoutRenderer` draws a `min-h-64` blank; **Change slide type** revives it). Nothing may assume a card has a block. A list whose last item goes is removed as a block; a comparison group keeps its heading.
- **List items are append-only** (`engine/listItems.ts`, `store.addListItem`): a new placeholder item (`NEW_ITEM_TEXT`) goes at the end so no position-keyed formatting slides; `MAX_LIST_ITEMS = 12`; `listTarget` never guesses between two lists. Written immediately after dropping pending `blockText:`/`inline:` saves. After adding, the **list group** is left highlighted (selected element, no item, not editing) — with an item selected the list's own box is hidden, so the group you just grew would never show as picked. Adding is done by a **plus drawn under a selected list** (`ElementActions`), not a toolbar button; it shows only when `canAddItem(blockIndex)` (`listTarget(blocks, i) === i`, i.e. a list with room).
- **Add content** (`engine/newContent.ts`, `store.addBlock`, the tools panel's Insert section — a button that, once pressed, reveals the type grid; needs a slide selected): appends one block — Heading 1/2/3, Body text, Bullet list, Stat, Quote, Timeline step, Comparison group (no image: needs a `url`) — to the **end** of the card. Append-only for the same reason as list items: inserting shifts every later block's `textRef`/`adjusts`/`inline` key. `MAX_BLOCKS = 20`. The layout engine decides where it draws (it may re-classify the card); the user drags it from there. The new element is selected and its first run opened (`firstEditableField`); `isPlaceholderText` makes `EditableText` select the whole placeholder on arrival. Headings carry an optional `size` (`'h1'|'h2'|'h3'`, absent on everything the AI writes = the layout's own size): passed as `Heading`'s `size` by `BlockRenderer` and the frames that draw headings (hero draws its own h1 and ignores it); the PPTX adjusted path honours it, the merged `body` path draws it as an ordinary paragraph.
- **Marks** (`engine/marks.ts`): flag marks bold/italic/underline; **value marks** `color`, `fontFamily`, `fontScale` (`VALUE_MARK_TYPES`, stored with a `value`; older marks without one are flags). No toggle: `applyValueMark` *replaces* in range (clipping neighbours), `null` clears; `normalizeMarks` treats value as identity; size is a **multiple** of surrounding text (`em`). With characters selected in an edited run the toolbar font/size/colour go to `store.setTextMarkValue` (coalesced on `markValue:<card>:<ref>:<type>`), else to element/card/deck. Controls show the value at the selection's first character. `EditableText` does **not** clear the reported range on blur (the native colour input must take focus). Run values beat element values via inline declarations on the run's span.
- **Element typography** lives in `card.inline` under a bare block index (`blockStyleKey`) beside per-run `textRef` entries (`parseTextRef` needs `index:field`, so no ambiguity); `store.setInlineStyle` serves both. **Text colour** is a whole-element `TextStyle` field (`#rrggbb`, absence = theme). It needs two mechanisms because layouts colour text with utilities on the elements: `data-deck-color` + `--slide-user-color` matched by an **unlayered** rule in `index.css` (beats Tailwind's layered utilities; text on an accent fill is excluded), and `Adjustable` sets the same attribute + inline `color` on its own node.
- **Bin and plus on the selected element** (`components/editor/ElementActions.tsx`, mounted by `SelectionLayer`): a bin outside the element's top-right corner (removes the picked item, else the element — the explicit request works even mid-edit and ends the edit; Backspace still only removes while not typing) and, for a list with room, the plus under its left edge. Drawn in the element's own rotated frame so they follow rotation. `SelectionLayer` measures the selected element even while an item is picked (the box/handles hide, the actions stay). Both buttons stop the press **and the click**: the card's own click handler resets selection to the card and would clear the element a moment before the action ran. Callbacks reach them through `BlockAdjusting` (`remove`, `canAddItem`, `addItem`).
- **Toolbar align**: `renderedAlign` (`useRenderedAlign`) reads the computed `text-align` (hero/quote/statHero centre by CSS class, and untouched elements have no stored value); `normalizeAlign` maps start/end, refuses `justify`. Clicking always **sets**. An explicitly aligned element is stretched (`stretchesInFlexColumn`, **column** flex parents only — in a row `align-self` runs the vertical axis) so alignment has room to act.
- **Font preview on hover**: `onFontPreview` in the panel sets `fontPreview` in `EditorPage` (`undefined` = none, `null` = theme font); `previewFont` (`engine/fontPreview.ts`, pure, tested) derives copies of the cards/deck text style with the font applied at exactly the scope a click would write (characters → element → card → deck) and only `CardCanvas` reads them — nothing is stored, no history entry, and `applyTextStylePatch` (`engine/textStyle.ts`, also used by the store's three style writers) is shared so preview and edit cannot diverge. The preview clears on pointer-leave, on pick, and when the picker unmounts.
- **Size and zoom are number inputs** (`PercentField`: committed on Enter/blur, Escape abandons via a ref because blur is what commits, non-numbers revert) beside step buttons (a big A with an up arrow / a small A with a down arrow for size; −/+ for zoom in the header). Size stays a **percentage of the theme's own scale** (`fontScale`, 70–160%, 50–300% for a character range), not points: an absolute size would flatten the theme's h1/h2/body steps. Every route (typed, stepped) goes through the same clamp.
- **Layout picker is a strip of real previews** (`LayoutStrip` in `ToolsPanel`, the Layout section): each option is the card's own content drawn in that layout by `SlidePreview` (`components/editor/SlidePreview.tsx`, the one fixed-16:9, width-fitted, cropped-at-the-bottom slide thumbnail shared with the dashboard's `DeckThumbnail`), with `adjusts` stripped so nudges don't make every option look alike. Varieties of the card's own type only, Automatic first. The theme picker is the same idea, small: `ThemeStrip` (horizontal scroll, `scrollbar-none`).
- **Zoom** is a CSS transform (`components/editor/ZoomFrame.tsx`, `lib/zoom.ts`): layout stays in card pixels; the scroll area gets the *scaled* height and the column its real width with auto margins (no transform-origin overflow into unreachable space); no transform at 100% so cards never remount. Clamped 50–200%, multiplicative, keeps view centre on the same content, not stored or undoable. Ctrl+wheel is a native non-passive listener (React's `onWheel` is passive). **Every gesture divides by the zoom** (`SelectionOverlay` drag deltas, rotate angle multiplies back, `measureAt` divides by drawn/laid-out width ratio) or elements run ahead of the pointer. **Ctrl+drag pans** (`useCanvasPan.ts`, `lib/pan.ts`): capture-phase native listener so it beats element selection; swallows the resulting click and Ctrl+click's context menu; cursor via `data-pan-ready`/`data-panning`.

### Element nudging (`engine/blockAdjust.ts`, `engine/frameGeometry.ts`, `components/layouts/Adjustable.tsx`, `components/editor/SelectionLayer.tsx`)

- `BlockAdjust = { dx, dy, w?, h?, rotation }` keyed by block index on `card.adjusts`; a **delta**, not a position, so other elements keep flowing and it survives text edits and layout switching. **Units are fractions of card content width** (height too, so aspect is stable at every card width). Displacement is a `transform` (siblings never move); only width/height participate in layout. A nudge that returns to neutral is **deleted**, not stored as zeroes (presence routes a card down the export's per-element path).
- **`Adjustable` is a `display: contents` wrapper** so it can wrap anything without changing layout; the adjustment is applied **imperatively to the child node**. Nested holders are guarded (`AdjustedIndexContext`; `measurableNode` walks past holders) — without it the selection box collapses to a dot. Every place a block renders must be wrapped (layouts' own `h1`/`p`, quote, `GroupRenderer` items); `Heading`/`StatBlockView` derive their index from `textRef`.
- **A resize probes the layout at the new size** (`measureAt`) before computing displacement, since `items-center` etc. re-position a resized child; without it the anchored edge slides. `adjustStyle` emits `maxWidth: none` alongside a width (readability caps like `max-w-prose` would silently win). `frameGeometry.ts` is pure: `resizeFrame` rotates the drag into element axes, applies it to the handle's axes, pins the *anchor* (opposite corner/edge midpoint), clamps at min size. Natural rects are measured (`measureNatural` clears imperative styles, reads, restores within one layout pass; clearing the transform matters because a rotated element's `getBoundingClientRect` is axis-aligned). **Every gesture is computed from the frame captured at the press**, never the live one (`measureBlock.test.ts` pins the round-trip).
- `SelectionOverlay`: interior `pointer-events: none`, border is not (edge drags move; the middle stays click-through for the caret).
- **`BlockDataContext` (data) vs `BlockAdjustContext` (interaction) is a load-bearing split**: every surface that draws a slide provides the data (`SlideBody` takes the card as a prop) so nudges, marks and typography render in the presenter and thumbnails, not only on the canvas. Marks are read from `BlockDataContext` too, never from editor-only `TextEditingContext`.
- Only the selected card shows a selection box; `TextEditingContext` is gated on card selection. Element typography is applied imperatively by `Adjustable` as `--slide-size-*` so theme h1/h2/h3/body ratios survive scaling.

### Card types (`engine/cardTemplates.ts`, `components/editor/CardTypeModal.tsx`)

The modal (`CardTypeModal`) is add-only: a slide's type is chosen once, when it is created, and **cannot be changed afterwards** (a reshape moves text to different block indices, which marks/nudges/typography are all keyed by). To put more on an existing slide use Add content. `layoutEngine.ts` reads a type off a card; `cardTemplates.ts` writes one (pure, no store/React).

- New cards are placeholder text (`starterBlocks`), never a generation call. `title` is the one type that names its layout (`layoutForKind` → `'hero'`; everything else `'auto'`); `cardTemplates.test.ts` pins that every type round-trips through the classifier.
- `contentLines` (still here) flattens a card's words minus its heading; narration reads it.
- `gallery` cannot be created (no way to supply an image `url`). New slides land after the active card (`withCardAfter`). The Level 2 layout button names the card's type.

## Theme system (the main styling gotcha)

`src/index.css` defines two parallel CSS-variable namespaces bridged into Tailwind v4 via `@theme inline` (no `tailwind.config.*`).

- **`app-*`** (`--app-background`, `--app-accent`, …): all editor/app chrome (`bg-app-*`, `rounded-app-*`) — never changes with a deck's theme. Light and dark are **separate purpose-built palettes** (dark is near-neutral black, not the darkened light palette, which read visibly purple). `--app-accent-text`/`--app-highlight-text` are AA-safe as text on the page background; `--app-highlight-foreground` is dark ink for text on a solid highlight fill. `--app-accent`/`--app-highlight` are for fills.
- **App light/dark** (`lib/appTheme.ts`, zustand, applied at module load): `mode` (`'system'|'light'|'dark'`, the setting, stored as a real value) vs `theme` (`'light'|'dark'`, what it resolves to). Paint code reads `theme`; only the settings modal reads `mode`. The OS `change` listener keys off `mode === 'system'`. `[data-theme='dark']` overrides only `app-*`; `dark:` is rebound to that attribute via `@custom-variant`. `ThemeToggle` (two-state, commits to the rendered side) is for `/login`. **`AuthVisualPanel` and dashboard `AppSidebar` are deliberately always-dark** (use `ThemeToggle`'s `onDark` prop there).
- **`slide-*`** (`--slide-background`, `--slide-accent`, `--radius-slide`, …): the deck's theme, applied only inside a scoped `ThemeProvider` (`display: contents` div, `applyTheme(theme, ref)` from `lib/theme-tokens.ts`), never on `<html>`. `layouts/*` use `slide-*` exclusively; `components/ui/*` use `app-*` exclusively. `ThemeProvider` is instantiated around `CardCanvas`, sidebar thumbnails, `PresentPage`, and each `ThemePanel` preview (it also provides the theme as React context).
  - **`applyTheme` must stay in `useLayoutEffect`** — a passive effect paints one frame with `:root` fallbacks (a flash of the wrong palette on every mount).
  - **Read the slide fonts as `var(--slide-font-heading)` / `var(--slide-font-body)` (`SLIDE_HEADING_FONT`/`SLIDE_BODY_FONT` in `theme-tokens.ts`), never via a `--font-slide-*` alias**: an `@theme inline` alias is substituted once on `:root` and blinds every scoped override (theme fonts and toolbar picks never reached slides). A test fails if a component uses the alias. **Every element carrying words sets one of the two fonts on its own root** (the node `Adjustable` overrides), else it inherits the chrome font.
- `BUILTIN_THEMES` is the only source (no custom themes). Five celestial presets: Moonlight, Cosmic Observatory, Deep Space, Solar Flare, Aurora — **ids stay `minimal/editorial/midnight/bold/sage`** (deck rows key on them). Decks store the whole theme as JSON, so `loadDeck` runs it through `resolveTheme(stored)` (match on `id`) so old decks pick up redesigns and never lack `celestial`/`accentSoft`. `ThemePanel` is preset-only. `darken()` derives `--slide-canvas-background` (and `--app-canvas`).
- **Celestial backdrops** (`lib/celestial.ts`, `components/theme/SlideBackdrop.tsx`): each theme has a `celestial` field as CSS/SVG layers, never images. `applyTheme` writes only the glow (`--slide-backdrop-image`); `SlideBackdrop` reads the theme from `SlideThemeContext` (`slideThemeContext.ts`, separate file for fast refresh). Each theme uses two or three decoration kinds, never all (`theme-tokens.test.ts`). Positions are % of the card, radii px (`circle <r>px`; orbits/bodies use `aspect-ratio: 1`; constellation SVG `preserveAspectRatio="none"` + `vector-effect="non-scaling-stroke"`). A star field is **one** element (`starFieldCss` composes N radial-gradients). The sky is **seeded on the theme id** (deterministic across renders/thumbnails/preview — `Math.random()` would reshuffle). `starPositions` is shared with the PPTX export; **its `rand()` draw order is load-bearing** (a star rejected by `avoidCenter` consumes exactly its x and y draws). `avoidCenter` keeps stars off the heading band; every palette's pairings are AA-checked.
- `components/theme/SlideSurface.tsx` is the shared card chrome (surface + backdrop + content, `isolate`, `overflow-hidden`); `CardCanvas`, `PresentPage` and the thumbnails all route through it. `ThemeStrip` previews are real `SlideSurface`s at 640×360 scaled with `transform: scale()`.

- **Dashboard** (`pages/HomePage.tsx`, all dashboard pages via `components/home/DashboardShell.tsx`): always-dark `AppSidebar` rail + light main column; below `lg` the rail is an off-canvas drawer (state in `DashboardShell`, no duplicate mobile header). Rail nav: **Workspace** (Overview `/`, Drafts `/drafts` with `useDrafts()` badge, plus `Join a class` for General accounts), **Classroom** (teachers: Classes, Students, Quizzes), **My classes** (students). - **Deck covers** (`DeckThumbnail.tsx`) are the first slide rendered live (real `SlideStage`/`SlideSurface`/`LayoutRenderer` at 800px, scaled to the tile's width in a fixed 16:9 frame, cropped at the bottom) — never a stored screenshot. `listDecks` fetches all covers in one query (`order_index = 0`; `cardMutations.ts` keeps orderIndex gapless); no cards → lettered `deckSwatch` gradient. The row→`Card` mapping is the shared `cardFromRow` (so `fetchDeck` and covers can't drift on the emphasis pass and older-row defaults).
- **Editor** (`pages/EditorPage.tsx`): floating left outline panel (`CardOutlineSidebar`) toggled by an arrow at its right edge's centre, and a right **tools panel** (`components/editor/ToolsPanel.tsx`, `RIGHT_PANEL_WIDTH_PX` 280, width-animated, collapsible by an arrow on its inner edge — tucked inside the window edge when collapsed, since the dock then has no width to centre on). There is **no floating toolbar**. The panel is **modelled on Figma's Design tab** (researched from Figma's help centre and UI3 blog; exact pixel specs were not available, so the structure and conventions are what is followed): a fixed header (undo/redo, Present, then a "Design" tab row with the **zoom on its right**, where Figma keeps it) above a scrolling body of **selection-driven sections in a fixed order: Layout → Content → Typography → Fill → Theme**. Layout and Content exist only while a slide is selected (Figma shows what the selected layer type has; nothing selected = page-level); Typography and Fill always write to the narrowest scope (character range → element → card → deck), named in muted text on the right of the Typography header (`scopeLabel`). Figma conventions used: sentence-case section titles with context or a small action on the right (Content's "+", Fill's "−" once a fill is set); a caption above each field; filled inputs with no border until hover/focus (`FIELD`); **segmented icon groups** where the selected option is a raised chip (`Segmented`/`SegButton`; B/I/U are independent toggles, alignment is exclusive); a tick on the current font; text colour is called **Fill** (Figma's name for it) — a swatch that is the native colour input, the value, and 12 presets; tooltips name every icon-only control with its shortcut. It is app chrome with its own surface (`app-*` tokens); its previews are the deck's theme on purpose. Every button refuses focus on mousedown so a run's caret and character selection survive; the inputs (size, zoom, colour swatch) must take focus, and it works because `EditableText` does not clear the reported range on blur. The font list **expands in the flow** because a popup would be clipped by the panel's scroll area. `TopBar` is `1fr auto 1fr`: back arrow, centred title, then save status, icon-only Export (spinner replaces glyph), theme toggle, Narrate PPT link.
- **Outline thumbnails** are the real `LayoutRenderer` at 800×450 scaled with `transform: scale()`. The rail has **no visible scrollbar** (`scrollbar-none`) — load-bearing: thumbnails scale to the rail's *measured* width and a space-taking scrollbar creates a resize feedback loop with no fixed point. **Do not make it visible without restoring `scrollbar-gutter: stable`.** The Add-slide button sits outside the scroller, pinned to the bottom.
- `CardCanvas` sorts cards, wraps each in the slide surface, and draws via `LayoutRenderer`; `cardRefs` lets the sidebar scroll a card into view.

## Persistence (Supabase)

Migrations in `supabase/migrations/`; run any your project predates. RLS on deck tables is `owner_id = auth.uid()` (`cards` via a join to `presentations`); the `themes` table is legacy/unused.

- `0002` `cards.visual_style`; `0006` `cards.adjusts` (`jsonb default '{}'`); `0008` `cards.narration` (`jsonb default '{}'`). **0006 and 0008 gate every card write** (including delete/reorder/undo, and — for 0008 — deck creation itself), because `cardRow` names both columns on every upsert. `parseAdjusts`/`parseNarration` map the `{}` default back to `undefined` ("has the column" ≠ "was adjusted/narrated"; else every old deck looks adjusted/narrated and the export takes its approximate path).
- `0007` makes a card write bump `presentations.updated_at` (the dashboard displays and orders by it). `0009` classroom tables + RLS; `0010` role pin, `join_class` promotion, `delete_own_account()`. `0011` `presentations.generation` (does **not** gate card writes; written in a separate best-effort update). `0012` quiz code/type/settings columns + `create_quiz`/`get_quiz_for_taking`/`submit_quiz_attempt` (does **not** gate card writes; gates quiz generation, taking and posting **and the teacher classroom pages' reads** — see Quizzes).
- `presentationStore.ts` debounces title/theme (`scheduleSave`, 500ms) but persists structural changes (delete, reorder, undo/redo) immediately, all through `persistCardsSync`.
- **A debounced write must never be outrun by a read.** Both `EditorPage` and `PresentPage` call `loadDeck` on mount, so (1) `loadDeck` returns early when it already holds that deck id (the in-memory copy is newest; also keeps undo across editor↔presenter); (2) `flushScheduledSaves()` runs pending writes (`loadDeck` awaits it before reading a *different* deck; `EditorPage` also fires it on `beforeunload`, best effort) — counterpart to `cancelScheduledSaves`, which undo uses so an *older* value can't land last; (3) a released gesture is written immediately (`setBlockAdjust(..., commit)` via `startPointerDrag`'s `onEnd`, clearing the pending debounced copy first; no extra undo step since `pushHistory` coalesces on the same key). `store/saveTiming.test.ts` pins all three.

## Narration page (`pages/NarratePage.tsx`, `engine/narration.ts`, `ai/narrationPrompt.ts`)

`/deck/:id/narrate`: read-only slide viewer + per-slide spoken script for a cloned voice. Most decks arrive already narrated (from `speakerNotes`); this page's own call fills blanks or regenerates chosen slides. Design: `docs/superpowers/specs/2026-09-02-narration-page-design.md`.

- **Read-only by omission**: `SlideViewer` renders the same `SlideSurface`/`SlideBody`/`LayoutRenderer` chain as the presenter and simply doesn't provide `TextEditingContext` or the interaction half of `BlockAdjustContext` (no second render path). `SlideBody` is still needed for `BlockDataContext`. The viewer scales to fit and never scrolls (`SlideCanvas` + `lib/fitScale.ts`: laid out at 1000px then transformed, never scales up, takes the tighter axis; reads `offsetWidth/Height`, which ignore transforms — `getBoundingClientRect` would feed back into a fixed point).
- **`narration` is `{text, generated}`**; `narrationStatus`, `isRegenerable`, `isResettable` are derived, so nothing falls out of sync, and keeping `generated` makes "Reset to generated" literal. A blank script reads `empty` even if a generated copy survives (Reset stays offered).
- **`mergeNarration` writes only to slides the user selected**, whatever the model returned (pure, tested — the feature's core invariant). `isRegenerable` only decides which boxes start ticked. A generation is one call over an explicit set (single slide or ticked boxes in `GenerateScriptsModal`); the set drives both `narrationSlides` (unselected marked `SKIP`, still sent as context) and `mergeNarration`. Replacing hand-written words asks twice, on **both** routes (`ConfirmReplaceModal`). `generateNarration` goes through `FallbackProvider` (same capacity-only failover, retry, abort).
- **`narrationMaxTokens` is bounded both ways**: floor 5200 (gpt-oss-120b spends ~3,400 reasoning tokens; below that you get an empty completion and a 400 `json_validate_failed`, not a shorter script); ceiling 7000 (Groq counts *requested* output against its 8,000 TPM window; 8192 is refused outright). One script ≈ 141 tokens → ~20–25 slides max. **Above that it fails as a 400 (`request` kind), which does not fail over to Gemini.** The 10-slide cap keeps decks well under it.
- Typing debounces at 500ms and coalesces undo on `narration:<cardId>`; Reset and whole generations write immediately. `NarratePage` calls `flushScheduledSaves()` on unmount. The panel surfaces `store.status === 'error'` (a silent failed save of hand-typed text is the worst outcome; also how a missing migration 0008 announces itself). Accepted limitation: the brief (audience/tone) isn't stored on the deck, so narration infers tone from deck text.

## Quizzes (`src/quiz/`, `components/quiz/`, `pages/QuizPage.tsx`)

The editor's **Quiz** button (`QuizModal`) turns a deck into a quiz: multiple choice (A–C/A–D), fill in the blank (optional word box), true/false (`TRUE/FALSE` or `T/F`), 1–20 items (`MAX_QUIZ_ITEMS`), one type per quiz. Design: `docs/superpowers/specs/2026-09-24-quiz-generator-design.md`. A quiz is a **separate artifact generated from a deck on demand**; it never reads or writes `cards` and is **not precedent for a "regenerate this slide" button** (same carve-out as narration, see "Core rule: generate once"). No regenerate-in-place either: a new quiz is a new generation.

- **Free chain only.** `QUIZ_CHAIN` (`fallbackProvider.ts`) is `GroqProvider` on `openai/gpt-oss-120b`, then `groq/compound` — never Anthropic (billed) or Gemini. Empty without `VITE_GROQ_API_KEY`; the Quiz button is then disabled (`QuizProvider` in `ai/provider.ts` is deliberately not on `AIProvider`, so the other providers need no stubs). It shares `runWithFailover(chain, label, call, signal)` with `FallbackProvider` (the class delegates to it), so **capacity-only failover and cancel-never-hands-off are one code path**; `generateQuizWithFallback` is the entry point and `quizFallback.test.ts` mutation-checks that an `auth` failure does not fail over.
- **Budget** (`ai/quizPrompt.ts`): `quizMaxTokens(n) = clamp(n*110 + 3800, 5200, 7000)` (the 5,200 floor clears `gpt-oss-120b`'s ~3,400 reasoning tokens, 7,000 is Groq's ceiling; same reasoning as `narrationMaxTokens`). The deck text sent is capped at **600 characters per slide and ~6,000 in total** (`MAX_SLIDE_CHARS`/`MAX_TOTAL_CHARS`; every heading kept, body lines shared out of the total) because Groq's ~8,000 TPM window counts input **plus requested output**. 20 items on a very large deck is the tight case: a 429 there fails over to `groq/compound`, and if both are out the user sees "busy, try again". Raising either cap means revisiting this.
- **The model is not trusted for structure** (`quiz/build.ts` `buildQuestions`, pure): drops questions citing an out-of-range slide (a false citation is worse than a missing question) or whose shape doesn't match the type; trims to `count`; reports a **shortfall** rather than repairing with a second call; **shuffles multiple-choice choices client-side** with a seeded shuffle (models bias the answer position; the seed makes it testable), carrying the correct index with them. Replies go through zod (`quiz/schema.ts`) with one retry that sends the exact errors. The word box is not stored, it is derived at display time.
- **Storage (migration 0012 REQUIRED).** `quizzes` gains `code` (8 characters, the alphabet of `generate_join_code()`; `quiz/quizCode.ts` **must stay in step with `generate_quiz_code()`**, `quizCode.test.ts` checks it), `quiz_type` and `settings` (presentation only; scoring ignores it). `quiz_questions` stays **owner-only under RLS** — that is what makes the answer key and PDF owner-only *by data*. Students touch a quiz only through `get_quiz_for_taking` (never returns answers) and `submit_quiz_attempt` (**scores on the server**; one attempt per student per class; returns which were right, not the answers). `create_quiz` is `security invoker` (RLS decides who may save) and atomic. It **does not use `INSERT … RETURNING`**: it generates the id and code up front, because under invoker RLS `RETURNING` re-checks the SELECT policy `can_read_quiz`, which looks the row up in the table and cannot see it yet, so the insert would be refused. Don't "simplify" it back. The word-box flag is read as a JSON boolean (`settings->'wordBox' = 'true'::jsonb`, not a cast: `settings` is client-supplied and a bad value must not break taking).
- **0012 also gates the teacher classroom pages' reads.** `QUIZ_COLUMNS` (`classroom/rows.ts`) now selects `code` and `quiz_type`, so on a database without 0012 the Classes / Students / Quizzes loads **error** (same shape as 0006/0008 gating every card write). Generating from the editor fails with "Run migration 0012 in Supabase."
- **Rules.** Any deck owner can generate; only **Teachers** see a code and can post (a General account has no classes and account type is permanent; the modal says "Sharing needs a Teacher account"). A non-member with a code is **refused** ("join the class first") — a code never auto-joins a class. Posting is never at generation time: it is from the Quizzes page (`QuizRow`: Post to class menu, unpost chips, copy code/link), and the same rows appear in the class folder. Students arrive at `/quiz/:code` by link or the "Have a quiz code?" field on `MyClassesPage`. `classroom/stats.ts` is unchanged: a submitted attempt flows into the existing dashboard numbers.
- **PDF** (`quiz/pdf/`) is **owner-only by data**: the button exists only where answers were loaded through the owner's own `quiz_questions` read (`loadOwnerQuiz`), and a student session has none to print. `jspdf` is `import()`ed at export time (own lazy chunk, never in the entry bundle); Noto Sans regular/bold are fetched from `/fonts` (`public/fonts`, OFL) because jsPDF's built-ins are Latin-1 only, falling back to Helvetica with a warning. Latin, Greek and Cyrillic only — no CJK or Arabic. Layout (`quizPdfLayout.ts`) is pure; `quizPdf.ts` only draws.
- **Testing**: pure Vitest only — prompt and budget clamp (`quizPrompt.test.ts`), schema and `buildQuestions` (`schema.test.ts`, `build.test.ts`), the Groq call and failover against mocked `fetch` (`groqQuiz.test.ts`, `quizFallback.test.ts`), row mapping (`rows.test.ts`), taking logic (`taking.test.ts`), code (`quizCode.test.ts`), PDF layout (`quizPdfLayout.test.ts`). The modal, `QuizPage` and PDF drawing are not exercised in a browser. **`supabase/tests/0012_quiz_rls.sql` is hand-run** (like 0009/0010: students can't read `quiz_questions`, the RPC refusals, server-side scoring per type, one attempt, a General account can create but not post); on this branch it has **not yet been executed against a database**.

## Auth
