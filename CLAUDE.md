## Environment

- `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` (see `.env.example`). If absent, `supabaseConfigured` (`src/lib/supabaseClient.ts`) is `false`, store methods no-op, and `/login` shows an explanatory message instead of a form — nobody can log in, so the app is effectively unusable.
- `VITE_ANTHROPIC_API_KEY` (one chain link, first), `VITE_GROQ_API_KEY` (two chain links) and `VITE_GEMINI_API_KEY` (one), built into `PROVIDER_CHAIN` in `fallbackProvider.ts` (imported by `CreatePage.tsx` and the Narration tab) and **baked into the client bundle** — fine for local/personal use, readable by anyone who can load a deployed build. Any may be omitted (its provider drops out of the chain) but at least one is required; `/new` checks on mount. No in-app key entry, no server proxy, by design. **Unlike Groq/Gemini's free tiers, the Anthropic key is billed per token** — a deployed build isn't just readable, it's spendable; see `.env.example`.
- `VITE_CARTESIA_API_KEY` (optional): voice cloning and preview in the Narration tab. A **full-account** key, baked into the bundle; see Voice. Without it the Voice & video button and the menu's Narrated video item are disabled. Generating a video makes one `speak()` call per narrated slide, so a deployed build also lets anyone who loads it spend on the account in bulk.
- `VITE_PEXELS_API_KEY` (optional): photo search (`src/images/pexels.ts`, `searchPhotos`). Baked into the bundle like the others; the key is free but rate limited (200 requests an hour). Without it generated decks get no photos and the image picker is paste-link only (`imagesConfigured` is `false`; `PHOTOS_NOT_SET_UP` in `lib/setupCopy.ts`). An image block's optional `credit` (`{name, url, source: 'pexels'|'url'}`) is what the slide shows as "Photo: <name> / Pexels".
- **Users never see a key's variable name** outside `/new`'s and `/login`'s setup messages (screens for whoever runs the site): the quiz, voice and script-writing messages come from `lib/setupCopy.ts` ("…Whoever runs it needs to add a Groq key.") and the variable names go to the console (`warnMissingKey`). Render tests assert no `VITE_` in the narration tab and video dialog.
- Accounts are required: every route except `/login`, `/admin/login` and `/reset-password` is under `<RequireAuth>`. No guest mode. `store/authStore.ts` = Supabase email/password with email confirmation. `ensureSession()` only waits for hydration.

## Core rule: generate once

A deck's cards come from **one** AI call at creation and nothing afterwards asks the model for card content again. To get different content, start a new project. The user can still edit by hand (text in place, delete/reorder cards, nudge elements, add a slide, change slide type, add list items, remove elements) — none of that calls a provider. Research and repair happen *before* the deck exists, inside `generatePresentation`. Narration (`generateNarration`) is a separate field never rendered on slides or exported to PPTX — it is **not** precedent for a "regenerate this slide" button. Neither is a **quiz** (see Quizzes): a separate artifact generated from a deck on demand, it never touches `cards` and is no reason to let the model rewrite slides after creation.

Authority: the AI decides what a card says and which blocks it holds; the layout engine decides how it renders. Element nudges are *deltas* on top of the layout, never a replacement. There is deliberately no free-form canvas *for content*: the one free-positioned thing is hand-drawn **ink** (see Drawing layer), a separate overlay that never touches `blocks` and that the AI never writes.

## Creation flow

1. `pages/CreatePage.tsx` is a one-sheet brief (redesigned 2026-11-03; surface brief `.impeccable/surfaces/src-pages-createpage-tsx.md`): topic, slide count (chips 1–`MAX_SLIDES` or "Let AI decide" = `'auto'`), audience (General/Students chips or "Someone else" + free text; `audience` stays a free string downstream), detail level, optional focus/guidance, all visible and answerable in any order, beside a live `BadgePreview` of the deck's dashboard badge. Generate (or ⌘/Ctrl+Enter) needs topic, audience and detail; pressing it early names what's missing and focuses it. The draft is saved on every keystroke (see Brief drafts) and deleted once a deck is created. **The slide count is always shown, so it only counts as an answer once something else is answered** (else every visit to `/new` leaves a draft). Drafts saved by the old one-question flow still resume: their `pendingText` goes into the first unanswered field.
   - **Tone is removed from the intake, not from generation**: `DEFAULT_TONE` (`'professional'`, `ai/prompts.ts`) is still sent. Restoring it = `STEP_ORDER` + an `Answers` field + a section on the sheet (`STEP_ORDER` still drives draft progress, "N of 5").
   - Slide count (`lib/slideCount.ts`): `MAX_SLIDES = 7` (tightened from 10, deliberately "for now" — see its doc comment), `DEFAULT_SLIDE_COUNT = 5`, floor 1 (only the ceiling is enforced). **Raising `MAX_SLIDES` requires revisiting the Groq deck token budget and the narration budget** (below); past ~20 slides narration cannot complete.
   - `guidance` is injected into the user prompt as a hard constraint overriding the system prompt.
2. Generate saves the complete draft and hands the brief to `startDeckJob` (`jobs/start.ts`, see Background jobs), then navigates to `/`; the job calls `generatePresentation` (`src/generation/pipeline.ts`) with its own `AbortController`. After the pipeline and before the insert the job runs a cancellable **photo stage** ("Finding photos"; `generation/photos.ts` `addPhotos` with Pexels `searchPhotos`): it strips every model-written `image` block and appends one found photo to each card that has an `imageQuery`. It runs even without `VITE_PEXELS_API_KEY` (searching nothing, so invented image URLs are still stripped; `warnMissingKey` once); a non-cancel failure inserts the deck as generated, and `imageQuery` is never stored. Leaving `/new` cancels nothing, there is no leave prompt, and Generate is disabled while a deck job runs. **Every provider must honour the signal in both `fetch` and backoff `sleep`** — the panel's Cancel promises the request stops.
3. Output is validated against `generatedDeckSchema` (`generation/schemas.ts`, re-exported from `ai/provider.ts`). Enums (`plan.purpose`, `visualType`, `layoutFamily`, a claim's `type`) use zod `.catch(default)` so an off-list value never costs a deck; `plan`, `speakerNotes` and required shape still fail; each card's first block must be a `heading`. One retry is sent with the exact zod errors.
4. `store/presentationStore.ts` `insertGeneratedDeck(deck, requestedCount, result)` (write-only; what the background job calls) and `createDeckFromGeneration`, which wraps it and also replaces the open deck, atomically creates the `presentations` + `cards` rows, prefills each card's `narration` from `speakerNotes` (`{text, generated}` both the same string; blank note → unset), writes `presentations.generation` best-effort in a separate try/catch (a project lacking migration 0011 just warns), then navigates to `/deck/:id`.
5. `engine/emphasis.ts` `applyEmphasis` converts `*x*`/`**x**` into a **bold** mark in `card.inline` under the editor's `textRef`, stripping delimiters (marks are character offsets, so stripping at render time would desync). It runs at ingest **and** at the read boundary (`cardFromRow`) to convert older decks; hence it must be idempotent — a run that already carries marks is skipped entirely, delimiters included. The regex needs non-space run edges and no inner asterisk (keeps `2 * 3` alone).

"Skip and start blank" (`createDeck`) makes an empty project with no AI call.

### Blueprints (`ai/slideBlueprints.ts`)

Three (Informing & Training, Persuading & Selling, Storytelling & Engaging), each a 10-slide master sequence with the design doc's 5–10 scaling tables held verbatim (below 5, `sequenceFor` compresses the 5 column keeping opening and close). **The model picks the blueprint**, so the prompt carries all three candidate sequences (every column for `'auto'`). The sequence is **guidance, not rails**: merge/replace rows allowed, skip agenda-style rows unless formal; the slide count is still exact. `role` on a card is optional. `sequenceMismatch` only runs if some card has a `role`, and only warns (nothing can be regenerated, so a near-miss must not cost the deck). At ingest `roleLayoutHint` turns a role into an explicit layout where blocks support it (lets story `insight`/`closing-line` be heroes, since `chooseLayout` awards `hero` only to the first card); the role is then discarded (not stored).

### Token budgets (per provider, not shared)

- Groq `deckMaxTokens` (`ai/prompts.ts`): `clamp(n*480 + 2600, 5200, 7000)`, 7000 for `'auto'` — tuned to Groq's 8,000 TPM free tier, which counts *requested* output. The 5200 floor clears `gpt-oss-120b`'s ~3,400 reasoning tokens. Accepted risk: a 10-slide deck can truncate → fails shape check → one retry → error.
- Gemini `geminiDeckMaxTokens`: `clamp(n*700 + 3000, 6000, 12000)`, 12000 for `'auto'`.

## Generation pipeline (`src/generation/`)

`generatePresentation(provider, topic, brief, options)` → `{ deck, evidence, research, claims, flags, repaired }`. Stages: research → plan+write → validate → repair → re-validate. Design: `docs/superpowers/specs/2026-09-19-content-generation-pipeline-design.md`.

- **One plan+write call, not planner/writer/reviewer**: the writer is a reasoning model spending ~3,400 tokens thinking per call against an ~8,000 TPM window, so separate calls would trip the limit and triple the wait. Each card's `plan` (purpose, audienceQuestion, keyMessage, visualType, layoutFamily, transition, importance) is emitted in the same JSON *before* its `blocks`. `plan.layoutFamily` is no longer requested (nothing reads it; schema still accepts it).
- **Research is best effort and must never cost a deck.** One `provider.research(topic, brief, today, signal)` call returns `{sources, findings, disagreements}` as JSON in free text (JSON mode can't combine with a tool call). Any non-cancel failure → `evidence: null, research: 'failed'`. Skipped (`'skipped'`) when `ai/researchPrompt.ts` `isUserMaterialOnly(guidance)` matches phrases like "only use the/my/these facts" (a bare "only use" is deliberately *not* enough). Research/repair pass `maxRetries: 0` (a 429 right after a deck call meets a saturated window anyway); deck/narration keep the full retry policy. Research `maxTokens` is 4000 (2000 let a reasoning model exhaust the budget before writing the JSON). Gemini grounding is implemented to the documented API but **untested live**.
- `parseEvidencePack` is lenient about the wrapper (strips `【…】`, `extractJsonObject`), strict about content: drops sources with neither `url` nor `publisher`, drops findings whose surviving `sourceIds` are empty, returns `null` if no finding survives.
- **The model never writes a source object — only cites ids.** The pipeline attaches the pack's own `Source` records. `Claim.id` (`c${slide+1}-${n+1}`) and `Claim.verified` are computed by `verifyClaims` (`validation/evidence.ts`); `verified` needs ≥1 sourceId, all present in the pack, always false with a `null` pack.
- **Slide 1 is always a title slide.** The prompt's TITLE SLIDE section asks for one heading plus at most one short paragraph; `OPENING_NOT_TITLE` (medium, `REPAIRABLE`) sends a non-conforming slide 1 to repair; and at ingest `generatedLayout` (`engine/roleLayout.ts`) names card 0's layout `hero` outright (so it stays a title slide if moved; anything extra shows as hero leftovers).
- **Detail level sets slide density** (`ai/detailLevel.ts` `DENSITY`): visible-word range and ceiling, bullet items/length and paragraph length per level, rendered as the SLIDE DENSITY section of the deck **and** repair user prompts (the system prompts state no word limits of their own) and read by `BODY_TOO_DENSE` and `BODY_TOO_THIN` (detailed only, medium, `REPAIRABLE`). Balanced keeps the original 20-40/55 numbers. Change a level in that table, never in a prompt, or the prompt and validator disagree and repair trims what the prompt asked for.
- **Plain-language rules** (`ai/plainLanguage.ts` `PLAIN_LANGUAGE_RULES`, adapted from the humanizer skill: stock AI words, inflated claims, "not just X but Y", habitual threes, stacked hedges, em dashes) ride verbatim in the deck, repair and narration system prompts; the quiz prompt carries only the word-level layer `PLAIN_WORDS_RULES` (banned words, plain verbs, dashes), since its Groq window is the tightest (`plainLanguage.test.ts` pins all four). The prompt text itself has no long dashes, since models copy their prompt's punctuation; keep it that way. Prompt-only: no validator rule, no extra call. Kept under ~2,400 characters because it is input on every call against Groq's per-minute window.
- **Validation** (`validateDeck`) runs 19 pure rules split across `validation/structure.ts` and `validation/evidence.ts`, each yielding a `QualityFlag {type, severity, slideIndex?, message, suggestedAction}`. **Severities are deliberately conservative** — a false "high" buys an unneeded repair call, so an unsure rule reports `low` (logged, never repaired). `UNSUPPORTED_STATISTIC`/`MISSING_SOURCE` are `low` when there's no pack at all (no-evidence behavior is documented prompt behavior, not a defect); otherwise `high`/`medium` by pack strength.
- **List dominance is fixed in what the model writes, not the classifier** (`chooseLayout` draws every single `bulletList` as iconGrid/numberedList): the prompt's VISUAL CHOICE section binds `plan.visualType` to required blocks and caps bullet slides at ~40% (none adjacent). `LIST_DOMINANT` and `VISUAL_MISMATCH` (medium) are in `REPAIRABLE`. Chart visual types are deliberately not checked against `stat` blocks (would push the writer to invent numbers).
- **Repair fires at most once.** `repairTargets(flags)` picks slides with a high flag or a medium `REPAIRABLE` flag, ranks by (highs, mediums) desc, ties by index, caps at `MAX_REPAIR_SLIDES` (4). `applyRepairs` (`generation/repair.ts`) writes only to targeted, in-range, schema-valid slides; never changes deck length or mutates input; untouched cards keep object identity; a replacement omitting `role` keeps the original's (else story heroes silently vanish). Repair failure (non-cancel) keeps the unrepaired deck. After a landed repair the deck is re-validated and returned `claims`/`flags` are post-repair.
- **Ingest:** `speakerNotes` become `narration` **exactly as written — no citations appended** (a cloned voice reads it aloud). No on-slide citations and no references slide (each needs a block the renderer/export/editor understand; a references slide would also silently grow the slide count). `buildGenerationMeta` (`generation/meta.ts`) writes brief, sources, plans/claims re-keyed by **card id**, flags, research to `presentations.generation`. **The editor's fact check reads it** (`generation/factCheck.ts`, pure, tested): unsourced claims (not opinions; none when research was `skipped`, since the brief said to use only the teacher's material) become an amber notice under the top bar ("2 claims on slides 2 and 4 have no source. Review"), a dot on those outline thumbnails and `FactCheckModal` (by slide, unsourced first, sources linked, "I've checked this"). Checked claim ids go back into the row as `reviewed`. The row is read and written by `generation/metaRow.ts` in its own best-effort calls, never in `loadDeck`'s select (0011 must not gate opening a deck). No AI action anywhere in it ("generate once"); never shown in the presenter, video or export.

## AI providers (`src/ai/`)

`AIProvider`: `generateDeck`, `research`, `repairSlides`, `generateNarration`. All take an optional `AbortSignal`.

### Retry (`ai/retry.ts`, shared by `callGroq` and `callGemini`)

Retries `RETRYABLE_STATUS` (429/503) up to `maxRetries` (default `MAX_RETRIES` = 3). `backoffDelayMs` is pure: exponential 1s/2s/4s; a server `Retry-After` (seconds or HTTP-date; past date → 0) wins **only if longer**; clamped to `MAX_DELAY_MS` (20s) so a 60s TPM window doesn't read as a hang. `sleep()` is abortable — cancel must not wait out a timer.

### Fallback (`ai/fallbackProvider.ts`)

`FallbackProvider` implements `AIProvider` over an ordered chain built once in `fallbackProvider.ts` (`PROVIDER_CHAIN`), imported by both `CreatePage` and the Narration tab; all four methods go through one private `run<T>(label, call, signal)` failover loop. Chain: `AnthropicProvider` → `GroqProvider` on `openai/gpt-oss-120b` (research on `openai/gpt-oss-20b` with `browser_search`) → second `GroqProvider` on `groq/compound` (deck/repair/narration only) → `GeminiProvider` (`gemini-flash-latest`). `GroqProvider` takes `GroqModelOptions` (`deckModel`, `researchModel`, `researchTools`, `supportsResearch`).

- **Only `capacity` failures (429/503/413) hand off.** `AIProviderError` carries `kind` (`capacity|auth|request|response|unknown`) + status via `kindForStatus`. An `auth` failover would hide a mistyped key behind Gemini; `request`/`response` fail identically on the backup. This is load-bearing and mutation-tested.
- **Cancellation never hands off** (aborted signal or bare `AbortError`), or the deck the user walked away from still arrives.
- The compound link's `supportsResearch: false` makes `research()` throw `capacity` before any network call: `groq/compound-mini` returns 413 for any prompt whose built-in search runs, at every token budget. `capacity` makes the chain skip straight to Gemini.
- `groq/compound` ignores `response_format` and wraps replies (`**…**\n```json\n{…}`); `ai/jsonText.ts` `extractJsonObject` (first `{` to last `}`) is used by every JSON parser. JSON mode is still requested everywhere.
- A provider with a missing key is left **out** of the chain; `AnthropicProvider` is included only when `VITE_ANTHROPIC_API_KEY` is present, same pattern as the other two; dropping `VITE_GROQ_API_KEY` drops both Groq links → Anthropic-then-Gemini with no code change.
- **Research now runs through Claude's paid web search by default**, not Groq's free `browser_search` link, because Anthropic leads the chain for all four methods. This is a deliberate cost tradeoff (the user chose Claude end-to-end over the cheaper Groq-first-research default) — do not "fix" it back to research-only-on-Groq.

## Brief drafts (`src/lib/briefDrafts.ts`)

Unfinished briefs are drafts at `/drafts` (`DraftsPage`, sidebar badge). All reads/writes go through this file, so moving to Supabase later means rewriting only it.

- Storage is browser `localStorage` (`lekturac:brief-drafts:<uid>`), not Supabase; writes are try/catch'd (blocked storage → silently unsaved). Drafts don't follow the user across devices.
- **The key is namespaced by user id — load-bearing**: `signOut()` clears only the Supabase session, so a shared key would hand your briefs to the next account. `storageKey()` returns `null` while the session hydrates and reads/writes skip — never fall back to an un-namespaced key. The cache remembers its key and `useAuthStore.subscribe` invalidates on user change.
- `purgeForeignDrafts()` runs on sign-**in**, never sign-out (sign-out would destroy your own unfinished briefs; no server copy). Order in that subscription is load-bearing: drop cache → `listDrafts()` (lets `drainLegacyKeys()` adopt `lekturac:create-draft` and un-namespaced `lekturac:brief-drafts` into the current user) → purge. Purging first deletes the legacy list before migration. Purge collects keys before removing (removal reindexes).
- `BriefDraft` carries `pendingText` (text typed into the open question, restored into the first-unanswered step). `saveDraft` drops a draft with no answers and no pending text. `MAX_DRAFTS = 30` drops oldest; nothing expires on a timer.
- `useDrafts()` is `useSyncExternalStore`; `listDrafts()` caches its sorted array and rebuilds only on mutation/`storage` event — an unstable snapshot re-renders forever.
- Leaving `/new` is always free (a started generation is a background job; the draft survives until the deck exists, so a failed job's "Edit brief" returns to it). Resume is `/new?draft=<id>`, resolved once into a ref. Drafts are deliberately not decks (own `DraftRow`, not in `selectDecks`).

## Content model & layout engine (`src/engine/`)

- `contentBlocks.ts`: `ContentBlock` zod union (`heading`, `paragraph`, `bulletList`, `stat`, `image`, `quote`, `timelineStep`, `comparisonGroup`) and `Card` (`id`, `orderIndex`, `blocks`, `layout`, `visualStyle`, `textStyle`, `inline`, `adjusts`, `narration`). `cardSchema` allows `blocks: []` (a blank card is real); the *generation* schema still requires a heading.
- `chooseLayout(blocks, {isFirstCard})` is a rule-based classifier (no LLM): `hero`, `statHero`, `statGrid`, `comparison`, `timeline`, `quote`, `iconGrid`, `numberedList`, `textFocus`, `gallery`, `standardSplit`, `imageFocus`, `standard`. `resolveLayout` defers to it when `card.layout === 'auto'` (nearly every card). Only two things name a layout: the Level 2 picker and a `title` card added anywhere but the front (needs explicit `hero`). `cardKindOf` lets a named layout outrank blocks when reporting a card's type.
- `card.visualStyle` (`'structured'|'expressive'`) is picked by the AI per card; `LayoutRenderer` passes it as each component's `variant`, and each component branches its own JSX. Legacy rows default to `'structured'` at the read boundary.
- **Families vs frames.** *Families* (`statGrid`, `timeline`, `comparison`, `iconGrid`, `numberedList`, `gallery` — `FLOW_LAYOUTS`) render through `FlowLayout`, which draws blocks in author order via `inferGroups` → leaves through `BlockRenderer`, runs of same-type blocks through `GroupRenderer` (`boxes`, `statRows`, `timeline`, `timelineRow`, `columns`, `table`, `chips`, `numbered`, `checklist`, `split`, `gallery`; exhaustive switch). *Frames* (`hero`, `statHero`, `quote`, `textFocus`, `standard`, `standardSplit`, `imageFocus`) keep their own components; `LAYOUT_COMPONENTS` is typed to exclude the family names. `LayoutRenderer` hands `FlowLayout` the **resolved** layout (never `'auto'`) as `layout`, beside the stored one as `hint`. `hero`, `statHero` and `quote` compose themselves; every other frame and every family draws through `SlideFrame`. Heading size is uniformly `h2` (shared `Heading`) except opening `HeroLayout` (`h1`) — don't reintroduce per-layout variance.
- **Composition is read off the blocks, never stored** (`engine/composition.ts`, pure, tested). `slotsOf(blocks)` returns block **indices only**: `claim` (the first heading, not necessarily block 0), `lead` (the paragraph directly after the claim), `aside` (the card's lone photo; none when it holds two or more) and `body` (every other index, ascending). It is total: every index lands in exactly one slot (`composition.test.ts`, all cards up to four blocks), so nothing is moved, copied or renumbered and every `textRef`, `adjusts` key and `data-block-index` stays valid. `accentOwner(blocks, resolvedLayout)` names the **one block index allowed an accent fill**: the first `stat` of `statHero`, the first `comparisonGroup` of `comparison`/`comparisonTable`, else `null`. `FlowLayout` passes it to `GroupRenderer` as `accentIndex`; the fill carries `data-accent-owner`, and `accentBudget.test.tsx` caps a slide at one. Accent as text colour or a hairline rule is free; an expressive stat grid or stat list fills nothing. **No layout draws a fill behind a heading** (`noHeadingFill.test.tsx`); importance is size and contrast.
- **`SlideFrame`** (`layouts/SlideFrame.tsx`) is the frame of `StandardLayout`, `TextFocusLayout`, `StandardSplitLayout`, `ImageFocusLayout` and `FlowLayout`: a **head zone** (`data-slot="head"`, top-left: the claim through `Heading`, the lead through `BlockRenderer` with `lead`, i.e. `data-lead`, `SLIDE_SIZE.lead`, line height 1.35; the full width of its column, with no width cap of its own) and a **body zone** (`data-slot="body"`, `flex-1`, `SLIDE_GAP.section` below the head) that its child draws from the body indices. Each block is drawn once under its own index and the claim and lead keep their own `Adjustable`, so the zone wrappers are not elements and nudges, marks and selection are unchanged. A card with no heading has no head. The optional `aside` prop `{node, side, width: 'half'|'wide', index?}` puts a photo beside the text column from `SlideBody`'s 640px container width up (`@min-[640px]` grid, stacked below it); `index` names the block the caller drew so the frame removes exactly that one from `body` (split and image-focus pass the card's **first** image, so a second image stays in the body and is drawn there; without `index` only a lone photo is taken out, and with no `aside` the photo stays in `body`). The frame never centres vertically and never fixes a height: the claim is top-left on every ordinary slide and a slide with more content grows past 16:9.
- **Vertical placement belongs to the layout.** `SlideBody` is `flex-1` and its inner wrapper is a `flex-1` column, so a layout fills the 16:9 floor and is **not** centred by it. Frames that want centring ask for it on their own root with `my-auto` (`hero`, `quote`, `statHero`, the blank-card placeholder); with a background photo `PhotoStage` already fills the floor and sets the text bottom (hero) or middle (quote). A new frame must choose its own placement. **Two known costs of the move from a vertically centred layout to a top-anchored one, unverified in a browser as of 2026-11-14:** (a) ink (`card.overlay`) drawn before this change keeps its position while the content under it moved up on slides shorter than 16:9, so old ink can sit below what it marked; (b) an element nudged upward on such a slide keeps its delta and now starts higher, so it can land partly or wholly above the slide's top edge, where `overflow-clip` hides it (`clampFrame` only constrains new gestures).
- **Grounds** (`engine/composition.ts`, pure, tested; `Ground` is `'plain'|'tint'|'deep'`): `groundOfLayout(resolved)` puts `hero` on the deep ground, `quote` and `statHero` on the tint and every other layout on neither; `groundOf(card, context?)` resolves the card's layout as the surface does (`context ?? {isFirstCard: card.orderIndex === 0}`), and a card with no blocks is always plain (an empty card named `hero` draws only the blank placeholder, which must not paint the deep ground). The three callers that hand `LayoutRenderer` an explicit `isFirstCard` (`PresentSlide`, `SlidePreview`, `renderFrame`) pass the same object to `groundOf`, so a cover tile's ground matches its layout whatever its `orderIndex`. `SlideSurface` takes `ground` and stamps `data-ground="tint"|"deep"` (`GROUND_ATTR` in `adjustContext.ts`; a plain card carries none); `index.css` re-points the `--slide-*` colour variables inside `[data-ground]` (tint: `--slide-background` only, to `--slide-ground-tint`; deep: background, foreground, muted, accent, accent-foreground, accent-soft, border and surface all move to the deep colours), so `bg-slide-background` and every layout's own colour utilities follow and **no layout changed**. **Every `SlideSurface` caller must pass `ground`** (`slideGround.test.tsx` scans the source for it). **Text on a deep ground ignores every colour pick, like text on a photo**: the deck and card pick by the `[data-deck-color]` rule's `:not([data-ground='deep'])` exclusions, an element pick because `Adjustable` writes none inside one, character colour marks by an `!important` rule on inline-coloured nodes; muted and other theme-coloured text keeps the re-pointed tones, and picks are kept, not dropped, so they show on every other slide. Known and accepted: an accent fill on a deep slide is drawn inverted (light fill, deep ink) because the variables are re-pointed; an inline character colour on text over an accent fill inside a deep slide still shows; no test pins the `index.css` `:root` slide block to the default theme's values. `LayoutWireframe` follows `groundOfLayout` (`data-wire-ground`), and each `ThemeGrid` tile also draws its theme's deep ground with a bar of its ink; **a layout changing ground means changing its wireframe**.
- **Type and gap steps** (`lib/theme-tokens.ts`): `SLIDE_SIZE` (`eyebrow` 0.65, `lead` 1.2, `caption` 0.7, each `calc(var(--slide-size-body) * r)` resolved at the use site, so an element's or card's size pick carries) and `SLIDE_GAP` (`tight` 0.5rem, `group` 1.25rem, `section` 2.25rem; the values are `--slide-gap-*` in the `:root` slide fallback block of `index.css`, which themes do not override). **Three values only; don't add a fourth.** `tight` is the gap between claim and lead, `section` between head and body, `group` between body nodes, all in the `SlideFrame` layouts. `GroupRenderer`'s own inner gaps and the gaps inside `hero`, `quote` and `statHero` still use Tailwind spacing utilities and move to the scale in Phase 1b.
- **Photo placements** (`singlePhoto` in `engine/blockPartition.ts`: a card with **exactly one** image; two or more are a gallery and never a background). Frames receive `position` (= `card.orderIndex`). `HeroLayout`/`QuoteLayout` draw it as the slide's ground (`BackgroundPhoto` + `PhotoStage`, `layouts/BackgroundPhoto.tsx`): an absolute `Adjustable fixed` node at `inset: calc(-1 * var(--slide-pad))` against `SlideBody` (so it must be a **sibling** of the text, never inside a positioned wrapper), under a scrim (`from-black/75 via-black/40 to-black/20` for the hero, whose text sits in the dark bottom band; a flat `bg-black/60` for the quote, whose text is mid-slide, `scrim="even"`; white text stays above AA even on a white photo), with the text in `PhotoStage` (`data-on-photo`, at least the slide's 16:9 height from `100cqw`). **`SlideSurface` owns the padding as `--slide-pad`** (`padding="fluid"|"roomy"`; callers no longer pass `p-*`), so the bleed equals the real padding on every surface. **Text on a photo is white and ignores every colour pick** (deck, card, element, character marks): `index.css` forces `[data-on-photo]` text `#fff !important`, the user-colour rule excludes it, and `Adjustable` skips an element colour on a node inside `[data-on-photo]`. The stage is `pointer-events: none` except the `Adjustable`-wrapped elements, so the photo behind stays selectable. A `fixed` `Adjustable` is selectable with no move/resize/rotate (`SelectionLayer` draws `FixedOutline` and the bin **inside** the frame, `ElementActions inside`; `Measured.fixed` from `data-fixed-element`). `StatHeroLayout` puts the figure and photo in two halves (side by `position`; a `my-auto` grid, stacked below the 640px container width); `StandardSplitLayout` is the frame's `aside` (`width: 'half'`), on the right on even positions and the left on odd (both variants); `FlowLayout` draws a lone photo as an `aspect-[6/1]` band (~27% of the slide) first in the body zone, below the claim and lead, and skips its leaf by index (`inferGroups` untouched); `ImageFocusLayout` (classifier's `imageFocus`) is the `aside` on the left (`width: 'wide'`, 3fr beside 2fr), the claim, lead and the rest in the text column. The credit (`PhotoCredit`, `data-photo-credit`, plain-text "Photo: name / Pexels", **never a link** since slides sit inside `aria-hidden` previews and `<button>`s; nothing for `source:'url'`) is part of every photo's JSX, so it shows on every surface and is not an element. The wireframes draw a photo only for `standardSplit`, `imageFocus` and `gallery`; the hero/quote background photo, the stat hero's photo half and a family's photo band are not drawn.
- **Extra varieties are explicit choices only**: lists have `iconGrid|numberedList|checklist|splitList`, stats `statHero|statGrid|statList`, timelines `timeline|timelineRow`, comparisons `comparison|comparisonTable` (each in both visual styles). `layoutVarieties` lists them. **The classifier never awards the new ones** (ingest's `varyLayouts`, `engine/varyLayouts.ts`, may assign one as an explicit `layout` so neighbouring `'auto'` slides don't share an arrangement (`iconGrid`/`numberedList` → `checklist`, `statGrid` → `statList`, `timeline` → `timelineRow`, `comparison` → `comparisonTable`); it changes only `layout`, never blocks); the stored `layout` reaches the arrangement as `hint` to `inferGroups` (a hint for a different run type is ignored). The PPTX export maps them onto its five arrangements; no template in `cardTemplates.ts` uses them.
- **Grouping is derived at render, never stored; the invariant that makes it safe:** `inferGroups` never reorders, drops or duplicates a block and every block keeps its index (`groups.test.ts` checks exhaustively). A block's index is its `textRef`, `card.adjusts` key, `data-block-index` and editor selection, so grouping changes how a card looks and nothing else. Runs are **consecutive only**. A single bullet list is arranged `chips`/`numbered` by explicit layout, else the classifier's `iconGrid` rule (shared `MAX_CHIP_ITEMS`/`SHORT_ITEM_MAX_CHARS`). Hand-built groups would need stored groups (future work).
- **`hero`, `statHero` and `quote` must end with `<Leftovers blocks consumed />`** (`engine/blockPartition.ts` `leftoverBlocks`, total over any consumed list): each draws only the types it understands, so it names the indices it drew and leftovers keep their original index. A frame showing only the *first* of a type must name only that one. Everything on `SlideFrame` (`standard`, `textFocus`, `standardSplit`, `imageFocus`) and the families need none: the frame's body draws every index `slotsOf` gives it.
- Cards are presentation-shaped with a **16:9 floor, not a fixed ratio**: `SlideSurface` (`SLIDE_SURFACE_CLASS`) is `relative isolate flex aspect-video flex-col overflow-clip` (no `justify-center`; `SlideBody` has none either), and `SlideBody` is `flex-1` and fills it, so the surface centres nothing: a short slide is 16:9 with its layout placing itself (see Vertical placement) and a taller one grows with its content. This only works because the surface is `overflow-clip`, never `overflow-hidden`: with an aspect-ratio and `height: auto`, the automatic minimum height is the content height *unless the box is a scroll container*, and `hidden` is one (it would pin the box to 16:9 and cut the content off) while `clip` is not (the theme's corner radius still clips). Don't give the card container a fixed height or change `overflow-clip`.
- **Every surface lays a slide out at one width, `SLIDE_WIDTH_PX` (976, `lib/slideSize.ts`), and scales the picture**: the editor column (`ZoomFrame`), outline thumbnails and `SlidePreview` (that width plus the stage's `px-10` sides, with the vertical padding computed so a short slide stays centred in its 16:9 frame), the presenter (`ScaledSlide`, up to 1024 wide) and the video (`frameScale`). Load-bearing: nudges and resizes are fractions of the content width but text is in rem, so a card laid out at another width wraps differently inside boxes that scaled (a resized heading spilling over the paragraph on a dashboard cover). A new surface that draws a slide must do the same. **Layouts never use screen breakpoints** (`sm:`, `md:` …): a layout that changes with width uses a container query (`@min-[640px]:`) against `SlideBody`'s `@container`, or a slide is arranged one way in the editor and another in the presenter or phone view on a narrow screen (`components/layouts/slideWidthOnly.test.ts` scans every layout).
- `Enter` inside a run inserts a real `\n` (`insertTextAtCaret`); every run renders `white-space: pre-wrap` on live and read-only surfaces; a trailing newline gets `<br data-run-end>` purely so the caret has a box. Paste is plain text with CRLF normalised. Marks are character offsets, so this needed no other change.

### Editing model

- **Selection drills in**: a press on an unselected card selects the **card** (however precisely it hit an element); a second press takes the element (so card-scope formatting is reachable; the cost is one extra press before drag/resize handles). Then one press selects, a further press (or double-click) edits; Backspace/Delete removes only while not typing; Escape steps out item → list → card (the page's Escape handler stands down for a key already `preventDefault`ed). `EditableText` tells select-vs-edit presses apart by recording at pointer-down whether its element was already selected. Scope is read off the selection by `engine/textScope.ts` (element → card → deck; a character range only narrows marks and value marks, not whole-element font/size/align). `selectedBlockIndex` lives beside `selectedCardId` in `EditorPage`, written via one `apply(Selection)`. `Selection` carries `itemIndex`; an item is a refinement of its list (lit via `data-item-selected`; arrangements spread `useItemProps()` on item containers so a press there doesn't select the list). Items are not draggable/resizable. The card's accent ring (`CardCanvas` `showCardRing`) is drawn only while the card itself is the selection — once an element is picked its own selection box replaces it.
- **Undo/redo** (`past`/`future` in `presentationStore.ts`) snapshots the whole `cards` array (cap 50, reset on `loadDeck`, in-memory). It relies on `persistCardsSync(presentationId, previous, next)` diffing to delete dropped rows and upsert the rest (ids preserved, so undo of a delete re-inserts). Keys ⌘Z / ⌘⇧Z / ⌘Y in one `EditorPage` listener that ignores input/textarea targets **but not a live text run**: the browser's own undo stack only knows typing, so deferring to it made ⌘Z do nothing for a nudge, formatting or added element whenever a run was focused (which a highlighted element usually has). The store undoes everything; `EditableText` repaints a live run whose node text differs from the store's `value` (typing always leaves them equal, so a mismatch means undo/redo moved it), or the node would keep stale text and write it back on the next keystroke. `EditorPage` also drops a selection/edit that an undo left pointing past the end of the card.
- **Removal** (`engine/removeElement.ts`, pure): removing block N renumbers every later address — `textRef`, `adjusts` key, bare-index typography key in `inline`, runs, list-item keys — and drops the removed element's own. `blocks`/`inline`/`adjusts` are rewritten together and written **immediately** (`commitRemoval`) after dropping the card's pending `blockText:`/`inline:`/`adjusts:` saves (they captured old values and would put the element back). Keys that aren't addresses are kept. Removing the last element leaves a blank card (never deletes it; `LayoutRenderer` draws a `min-h-64` blank; **Change slide type** revives it). Nothing may assume a card has a block. A list whose last item goes is removed as a block; a comparison group keeps its heading.
- **List items are append-only** (`engine/listItems.ts`, `store.addListItem`): a new placeholder item (`NEW_ITEM_TEXT`) goes at the end so no position-keyed formatting slides; `MAX_LIST_ITEMS = 12`; `listTarget` never guesses between two lists. Written immediately after dropping pending `blockText:`/`inline:` saves. After adding, the **list group** is left highlighted (selected element, no item, not editing) — with an item selected the list's own box is hidden, so the group you just grew would never show as picked. Adding is done by a **plus drawn under a selected list** (`ElementActions`), not a toolbar button; it shows only when `canAddItem(blockIndex)` (`listTarget(blocks, i) === i`, i.e. a list with room).
- **Add content** (`engine/newContent.ts`, `store.addBlock`, the floating toolbar's **Insert** menu (`ContentGrid`, a picture grid; needs a slide selected)): appends one block — Heading 1/2/3, Body text, Bullet list, Stat, Quote, Timeline step, Comparison group, Image (opens `ImagePicker`; the block is added by `store.addImage` only once a photo is picked, and is selected without opening any text) — to the **end** of the card. Append-only for the same reason as list items: inserting shifts every later block's `textRef`/`adjusts`/`inline` key. `MAX_BLOCKS = 20`. The layout engine decides where it draws (it may re-classify the card); the user drags it from there. The new element is selected and its first run opened (`firstEditableField`); `isPlaceholderText` makes `EditableText` select the whole placeholder on arrival. Headings carry an optional `size` (`'h1'|'h2'|'h3'`, absent on everything the AI writes = the layout's own size): passed as `Heading`'s `size` by `BlockRenderer` and the frames that draw headings (hero draws its own h1 and ignores it); the PPTX adjusted path honours it, the merged `body` path draws it as an ordinary paragraph.
- **Marks** (`engine/marks.ts`): flag marks bold/italic/underline; **value marks** `color`, `fontFamily`, `fontScale` (`VALUE_MARK_TYPES`, stored with a `value`; older marks without one are flags). No toggle: `applyValueMark` *replaces* in range (clipping neighbours), `null` clears; `normalizeMarks` treats value as identity; size is a **multiple** of surrounding text (`em`). With characters selected in an edited run the toolbar font/size/colour go to `store.setTextMarkValue` (coalesced on `markValue:<card>:<ref>:<type>`), else to element/card/deck. Controls show the value at the selection's first character. `EditableText` does **not** clear the reported range on blur (the native colour input must take focus). Run values beat element values via inline declarations on the run's span.
- **A wider style write clears the same fields at narrower scopes** (`engine/styleOverrides.ts`, pure, tested; used by `setTextStyle`, `setCardTextStyle` and `previewFont`): style resolves element → card → deck, so without this a slide or element styled once by hand ignores the deck for good (the title slide that "doesn't change"). Only the fields in the patch, whether set or cleared; character marks are never touched. The cleared cards are saved on the card writers' own keys (`cardTextStyle:<id>`, `inline:<id>`) so a pending save holding the old override is replaced, not left to restore it.
- **Unreadable colours are dropped** (`engine/readableColor.ts`, pure, tested): a stored text colour (deck, card, element, or a character colour mark) under `MIN_TEXT_CONTRAST` (3:1) against the theme's slide background is removed on `setTheme` and when `loadDeck` opens a deck (written back through the same card-writer keys), so a colour picked on a light theme ("Black") cannot turn text invisible on Deep Space or Solar Flare. Readable picks survive theme switches as before. The check is against the plain ground only: a deep ground (the title slide) ignores picks at every scope instead, the same idea as text on a photo (see Grounds).
- **Element typography** lives in `card.inline` under a bare block index (`blockStyleKey`) beside per-run `textRef` entries (`parseTextRef` needs `index:field`, so no ambiguity); `store.setInlineStyle` serves both. **Text colour** is a whole-element `TextStyle` field (`#rrggbb`, absence = theme). It needs two mechanisms because layouts colour text with utilities on the elements: `data-deck-color` + `--slide-user-color` matched by an **unlayered** rule in `index.css` (beats Tailwind's layered utilities; text on an accent fill is excluded), and `Adjustable` sets the same attribute + inline `color` on its own node.
- **Bin, Replace and plus on the selected element** (`components/editor/ElementActions.tsx`, mounted by `SelectionLayer`): **Replace photo** beside the bin whenever the selected block is an image (including the hero/quote background photo, where both sit inside the frame): it opens `ImagePicker` and a pick calls `store.replaceImage` (one undo step, written immediately after dropping the card's pending `blockText:`/`inline:` saves; rewrites only `url`, `alt` and `credit` of that block, so every other block, `inline` and `adjusts` are untouched); a bin outside the element's top-right corner (removes the picked item, else the element — the explicit request works even mid-edit and ends the edit; Backspace still only removes while not typing) and, for a list with room, the plus under its left edge. Drawn in the element's own rotated frame so they follow rotation. `SelectionLayer` measures the selected element even while an item is picked (the box/handles hide, the actions stay). Both buttons stop the press **and the click**: the card's own click handler resets selection to the card and would clear the element a moment before the action ran. Callbacks reach them through `BlockAdjusting` (`remove`, `canAddItem`, `addItem`).
- **Toolbar align**: `renderedAlign` (`useRenderedAlign`) reads the computed `text-align` (quote/statHero centre by CSS class; hero and every claim are left-aligned, and untouched elements have no stored value); `normalizeAlign` maps start/end, refuses `justify`. Clicking always **sets**. An explicitly aligned element is stretched (`stretchesInFlexColumn`, **column** flex parents only — in a row `align-self` runs the vertical axis) so alignment has room to act.
- **Font preview on hover**: `onFontPreview` in the panel sets `fontPreview` in `EditorPage` (`undefined` = none, `null` = theme font); `previewFont` (`engine/fontPreview.ts`, pure, tested) derives copies of the cards/deck text style with the font applied at exactly the scope a click would write (characters → element → card → deck) and only `CardCanvas` reads them — nothing is stored, no history entry, and `applyTextStylePatch` (`engine/textStyle.ts`, also used by the store's three style writers) is shared so preview and edit cannot diverge. The preview clears on pointer-leave, on pick, and when the picker unmounts.
- **Size and zoom are number inputs** (`PercentField`: committed on Enter/blur, Escape abandons via a ref because blur is what commits, non-numbers revert) beside step buttons (a big A with an up arrow / a small A with a down arrow for size; −/+ for zoom on the right of the top bar). Size stays a **percentage of the theme's own scale** (`fontScale`, 70–160%, 50–300% for a character range), not points: an absolute size would flatten the theme's h1/h2/body steps. Every route (typed, stepped) goes through the same clamp.
- **Layout picker is a grid of wireframes** (`LayoutMenu`/`LayoutGrid` in `components/editor/LayoutPicker.tsx`, the floating toolbar's Layout menu, shown only for a clicked slide): each option is a low-fidelity `LayoutWireframe` (app-chrome tokens, 160×90 viewBox) of the arrangement, not the slide's own words. **Each wireframe mirrors its component's JSX** (`GroupRenderer` for families, the frame components otherwise, both visual treatments) — change how a layout looks and you must update its wireframe, or the picker promises one thing and the slide shows another. Varieties of the card's own type only; there is no Automatic option — a card on `'auto'` lights the variety it resolves to. The theme picker (`ThemeGrid` in `ToolsPanel`) is the same idea: a two-column grid of low-fidelity wireframes drawn straight from each theme's colour tokens (stage, card, accent, heading and muted bars), not rendered slides.
- **Grid** (`engine/gridSnap.ts` pure, `components/editor/GridOverlay.tsx`, `gridContext.ts`): a graph-paper overlay plus optional snap, view state in `EditorPage` beside zoom (not stored, not undoable, never on the presenter/narration/thumbnails — `SlideBody` draws it only when the editor's `BlockAdjustContext` exists). **The grid shares the frame's origin and unit: the top-left of `SlideBody`'s box — the slide's content area inside its padding, which fills the whole 16:9 floor (it is `flex-1`; the layout fills it and is not centred by it), so the grid spans the bands above and below short content and its origin does not move when text height changes — one cell = content width ÷ `GRID_DIVISIONS` (40), a heavy line every 5th** — so a snapped edge lands on a drawn line at any card width and zoom; change one side and you must change the other. Snap runs in `SelectionLayer.onChange` *after* the move clamp: a move snaps the visible (rotated-bounds) top-left; a resize snaps only the dragged edges and only for **unrotated** frames (the anchor is pinned in world space), never below `MIN_FRAME_*`. **Snap is on by default and independent of Show** (`DEFAULT_GRID` = `{show: false, snap: true}`): it governs drops with the lines hidden too, so every gesture lands on the invisible grid unless the user turns Snap off (the floating toolbar's Show grid / Snap to grid toggles). Rotation is not snapped by the grid (shift already steps it). **Untested in a browser** like the rest of the live editing DOM; only the arithmetic and the toolbar toggles are tested.
- **Drawing layer** (pen, marker, eraser, shapes; specs `docs/superpowers/specs/2026-09-26-drawing-layer-design.md` and `2026-09-26-shapes-design.md`; `engine/overlay.ts`, `penSettings.ts`, `lib/temporaryInk.ts`, `components/editor/OverlayLayer.tsx`, `DrawingSurface.tsx`, `ShapeSelectionLayer.tsx`, `drawingContext.ts`, `PenPopover.tsx`, `ShapePopover.tsx`, `InkControls.tsx`, `engine/shapes.ts`): ink is `card.overlay`, a list of items — strokes (`{id, kind:'stroke', tool:'pen'|'marker', color, width, points}`) and **shapes** (`{id, kind:'shape', shape, color, width, fill, x, y, w, h}`; the six `SHAPE_KINDS`: rectangle, rounded, ellipse, triangle, diamond, arrow) — in **fractions of the content width for x and y** (the unit of `adjusts`), so it scales with the card and zoom; the origin is the top-left of `SlideBody`'s full-height box (the slide's content area; the layout fills it), so ink and the pen/shape tools reach the empty bands above and below short content and ink stays put when text height changes while the slide is at its 16:9 floor; once a slide is taller than 16:9 its height is content-driven and ink keeps its distance from the top when text reflows (accepted). Bounds `MAX_STROKES_PER_CARD` 300 / `MAX_POINTS_PER_STROKE` 1500 are enforced at capture (`decimate`), at parse and at commit; `parseOverlay` drops malformed strokes and reads `[]`/missing as none. **`cardRow` must never name `overlay`** (`overlayRow.test.ts` mutation-checks it): it is the upsert every card save goes through, so a named column that doesn't exist breaks all saves (0006/0008). Ink is written by `persistOverlay` in its own best-effort update (`setOverlay` writes immediately; undo/redo write `overlaysToWrite(previous, next)` after the snapshot, which also re-writes ink for a card re-created by undoing a delete). Failure sets `store.overlayWarning` (an amber banner), **never** `status: 'error'`. **Migration 0013 is required to save ink and has not been applied by this work.** `SlideBody` draws `card.overlay` on every surface (presenter, thumbnails, narration viewer) at `z-15` (above content and grid, below the selection box); **temporary ink** (`pen.keep === 'temporary'`) lives in `localStorage` (`lekturac:temp-ink:<uid>:<deck>`, **user-namespaced with no un-namespaced fallback**, 500k-char cap, pruned to existing cards), is drawn only where the editor provides `DrawingContext`, and is never in the database, undo or export. `DrawingSurface` (mounted only while `tool === 'pen'`) captures the drag with pointer capture, computes points with `contentFraction(client, rect)` from the content box's rect captured at the press (**zoom-independent: the transform scales the rect and the pointer distance together, so no zoom value is used**), draws the live stroke from local state and **commits once on release** (one undo step, one write); it stops the press and click so drawing never selects. The eraser removes **whole strokes** (`inkHit` measures to segments plus the stroke's half-width) from the layer chosen by *Keep* and fades them while over. Escape leaves the pen before it steps the selection. **Shapes** share the overlay, its bounds (the 300 limit counts items, strokes and shapes together), its persistence, its undo and Keep (On slide / Temporary); colour and Keep are the pen's ("the ink"). The shape tool rubber-bands from the press corner (a click drops a default-size shape) with `normalizeShapeRect`, snapped to the grid when Snap is on, and commits **once on release**, then returns to Select elements with the shape picked. A picked shape (`selectedShape` in `EditorPage`, **separate from the element selection**; selecting a card/element clears it, an undo that removes it is treated as none via `activeShape`) gets `ShapeSelectionLayer`: the element `SelectionOverlay` with `rotatable={false}` (shapes don't rotate) plus the bin (`ElementActions`), snap via `snapMove`/`snapResize`, the live frame held in `SlideBody` state so the shape tracks the pointer and **committed once on release** (`changeShape` → `replaceItem` → `setOverlay`). Shapes are pressable only when the editor passes `onPressItem` (Select elements active) and only on what they paint (`pointer-events: visiblePainted`: outline, or area when filled), so an empty outline never blocks the text inside it and the presenter/thumbnails never take presses; `inkHit` uses the same rule for the eraser (`shapePolygon`: an ellipse is sampled, rounded is tested as a rectangle). The card's accent ring is suppressed while a shape on it is picked. Backspace/Delete removes the picked shape; Escape deselects it first. **The PPTX export ignores `card.overlay` (strokes and shapes) until sub-project 4**, so an exported deck silently lacks drawings. Temporary ink is editor-only (not shown in the presenter). Untested in a browser: the drawing gesture, pointer capture, eraser feel and popover; tested: the arithmetic, parsing, storage rules, row round-trip and small render smoke tests.
- **Zoom** is a CSS transform (`components/editor/ZoomFrame.tsx`, `lib/zoom.ts`): layout stays in card pixels; the scroll area gets the *scaled* height and the column its real width with auto margins (no transform-origin overflow into unreachable space); one tree at every zoom so cards never remount. **The column is always laid out `COLUMN_MAX_WIDTH_PX` wide and a narrower view scales the picture down (`fitScale` in `lib/zoom.ts`) instead of narrowing the column** — so opening the tools panel or the outline shrinks the cards without re-wrapping them. The drawn scale is `zoom × fitScale`, and that product (not the zoom setting) is what `CanvasZoomContext` carries. Clamped 50–200%, opens at `DEFAULT_ZOOM` 90% (100% is one step in), multiplicative, **anchored**: Ctrl+wheel keeps the spot under the cursor still and the buttons/typed value keep the view's centre (`zoomAnchor`/`scrollKeepingAnchor` in `lib/zoom.ts`, as fractions of the `[data-zoom-content]` box measured before and after), not stored or undoable. The canvas has generous margin (`px-12 py-14`, `gap-14` between slides). **Two fingers pinch-zoom** on a touch screen (`zoomFromPinch`, measured from the start of the pinch, anchored between the fingers): native non-passive touch listeners, and the canvas is `touch-pan-x touch-pan-y` so one finger still scrolls but the browser never zooms the page. The canvas listeners (wheel, pinch, pan) re-attach when the canvas appears (`canvasShown`: not in the phone view). Ctrl+wheel is a native non-passive listener (React's `onWheel` is passive). **The canvas has no horizontal scrollbar** (`overflow-x-hidden`; a hidden overflow still scrolls from script, so panning works): the same listener scrolls it sideways for a trackpad swipe or Shift + wheel (`horizontalWheelDelta` in `lib/pan.ts`). **Every gesture divides by the zoom** (`SelectionOverlay` drag deltas, rotate angle multiplies back, `measureAt` divides by drawn/laid-out width ratio) or elements run ahead of the pointer. **Ctrl+drag pans**, and so does **holding the right button and dragging** in every tool (`isPanPress`; a right-drag's context menu is swallowed, a still right-click keeps it) (and a plain drag in the Move screen tool; `useCanvasPan.ts`, `lib/pan.ts`): capture-phase native listener so it beats element selection; swallows the resulting click and Ctrl+click's context menu; cursor via `data-pan-ready`/`data-panning`.

### Element nudging (`engine/blockAdjust.ts`, `engine/frameGeometry.ts`, `components/layouts/Adjustable.tsx`, `components/editor/SelectionLayer.tsx`)

- `BlockAdjust = { dx, dy, w?, h?, rotation }` keyed by block index on `card.adjusts`; a **delta**, not a position, so other elements keep flowing and it survives text edits and layout switching. **Units are fractions of card content width** (height too, so aspect is stable at every card width). Displacement is a `transform` (siblings never move); only width/height participate in layout. A nudge that returns to neutral is **deleted**, not stored as zeroes (presence routes a card down the export's per-element path).
- **`Adjustable` is a `display: contents` wrapper** so it can wrap anything without changing layout; the adjustment is applied **imperatively to the child node**. Nested holders are guarded (`AdjustedIndexContext`; `measurableNode` walks past holders) — without it the selection box collapses to a dot. Every place a block renders must be wrapped (layouts' own `h1`/`p`, quote, `GroupRenderer` items); `Heading`/`StatBlockView` derive their index from `textRef`.
- **A resize probes the layout at the new size** (`measureAt`) before computing displacement, since `items-center` etc. re-position a resized child; without it the anchored edge slides. `adjustStyle` emits `maxWidth: none` alongside a width (readability caps like `max-w-prose` would silently win). `frameGeometry.ts` is pure: `resizeFrame` rotates the drag into element axes, applies it to the handle's axes, pins the *anchor* (opposite corner/edge midpoint), clamps at min size. Natural rects are measured (`measureNatural` clears imperative styles, reads, restores within one layout pass; clearing the transform matters because a rotated element's `getBoundingClientRect` is axis-aligned). **Every gesture is computed from the frame captured at the press**, never the live one (`measureBlock.test.ts` pins the round-trip).
- `SelectionOverlay`: interior `pointer-events: none`, border is not (edge drags move; the middle is click-through). **A selected element also moves when dragged from anywhere on its body** (`Adjustable` → `BlockAdjusting.startMove`, which `SlideBody` re-provides and fills from `SelectionLayer`'s frame): `startPendingDrag` (`pointerDrag.ts`) turns the press into a move only past `DRAG_THRESHOLD_PX` (4px), so a still click still opens the text for editing, and the click ending a drag is swallowed. Not while that element's text is open (`canGrab`): a press there places a caret, and the edge is the way to move it. With a whole list selected, a press on an item grabs the list, and only a still press picks the item. The move cursor is `[data-element-grabbable]` in `index.css`.
- **`BlockDataContext` (data) vs `BlockAdjustContext` (interaction) is a load-bearing split**: every surface that draws a slide provides the data (`SlideBody` takes the card as a prop) so nudges, marks and typography render in the presenter and thumbnails, not only on the canvas. Marks are read from `BlockDataContext` too, never from editor-only `TextEditingContext`.
- Only the selected card shows a selection box; `TextEditingContext` is gated on card selection. Element typography is applied imperatively by `Adjustable` as `--slide-size-*` so theme h1/h2/h3/body ratios survive scaling.

### Card types (`engine/cardTemplates.ts`, `components/editor/CardTypeModal.tsx`)

The modal (`CardTypeModal`) is add-only: a slide's type is chosen once, when it is created, and **cannot be changed afterwards** (a reshape moves text to different block indices, which marks/nudges/typography are all keyed by). To put more on an existing slide use Insert. `layoutEngine.ts` reads a type off a card; `cardTemplates.ts` writes one (pure, no store/React).

- New cards are placeholder text (`starterBlocks`), never a generation call. `title` is the one type that names its layout (`layoutForKind` → `'hero'`; everything else `'auto'`); `cardTemplates.test.ts` pins that every type round-trips through the classifier.
- `contentLines` (still here) flattens a card's words minus its heading; narration reads it.
- `gallery` cannot be created (it holds several photos and the picker chooses one at a time). **`image` is a creatable type that is born from a photo**: choosing it in the modal opens `ImagePicker` and the card exists only once a photo is picked (cancelling creates nothing); `starterBlocks('image', photo)` requires the photo (heading `Image title`, the image block carrying the photo's alt and credit, paragraph `Add a caption`) and `layoutForKind('image')` is `'imageFocus'`. New slides land after the active card (`withCardAfter`). The Level 2 layout button names the card's type.

## Motion (`src/lib/motion.ts`)

Chrome motion is GSAP: `useMotion(setup, deps)` runs presets inside a `gsap.context` (reverted on unmount/deps change), plus stable ref callbacks (`dropFromTop`, `riseInRef`) for panels that mount when opened. Used by `DashboardShell` (the track band prints, then the head rises), `HomePage` (deck list, on load and view switch only), `Modal` (opening only; closing is instant), `ToolbarMenu`/`TopBarMenus` panels and `/new`. Every preset is `gsap.from` with `clearProps`, so content is visible by default and CSS (e.g. a deck card's hover lift) owns the element again afterwards; every preset has a reduced-motion path. **Never animate a slide surface, the editor canvas or anything `SelectionLayer`/`measureBlock` measures**: a leftover transform skews `getBoundingClientRect` and every gesture computed from it. GSAP core is now in the entry bundle (the welcome page's plugins stay in its lazy chunk).

## Presenter view (`src/present/`, `components/present/`)

Present ▾ → Presenter view splits a talk over two windows on one computer: the tab becomes the **console** (`PresenterConsole`: current and next slide, the read-only `card.narration` script, timer, pacing) and a second window the **slide window** (`SlideWindow`, for the projector). Same route as Present, picked by `?view=presenter|screen&session=<id>` in `PresentPage` (no param = the old single window); both stay under `RequireAuth`. Spec: `docs/superpowers/specs/2026-11-12-presenter-view-design.md`. **No network, AI, database or migration**, and it never touches `cards`: the script is whatever the Narrate tab holds, so it is not precedent for a generation button.

- **The console owns all state** (`presenterState.ts` reducer, `pacing.ts`, `timer.ts`, all pure); the slide window renders what it is sent and forwards its keys (`key` actions, so Next on either window is one code path). Windows talk over `BroadcastChannel` `lekturac:present:<session>` and **every message is zod-parsed** (`protocol.ts`): another window's data is untrusted.
- **The deck is a frozen snapshot** sent in a `deck` message (`{title, theme, textStyle, cards}`), so the slide window never reads Supabase and edits made after starting do not appear. Both windows draw through `PresentSlide` and `FittedSlide` (scales by width **and** height with `frameScale`, laid out at `SLIDE_WIDTH_PX` like every surface); only `frameScale` is imported from `src/video`, keep it that way.
- **A reload resumes**: the session id and `SavedSession` (slide, black, ended, stopwatch, target, `startIndex`) live in the tab's `sessionStorage` (`session.ts`, every access in try/catch), because a clicker's "start show" key can reload the console mid-lesson; on mount it pings and an open slide window answers `hello`. "Presentation ended" is not final: a later `deck`/`state` brings the slide back.
- **Liveness is silence, not `popup.closed`** (a reloaded console has no window reference): the slide window posts `alive` every 1 s and the console shows the Reopen banner after 3 s without one (`nextScreenLink`, pure). A window still loading has not posted yet, so `connecting` (from mount or the last Open/Reopen click) gets its own 10 s grace (`CONNECT_GRACE_MS`) and the 3 s rule applies only once something has been heard. Reopen uses the named target `lekturac-slides` so a live window is reused. The slide window **never closes on its own**: `bye` (the console is gone) only blacks it, so the desktop is never shown on the projector; only `end` (End presentation) closes it.
- **`window.open` runs inside the click** (the menu item, and the console's Open/Reopen buttons) or pop-up blockers refuse it (Safari's activation window is about 1 s): `openSlideWindow` first, then navigate to the console. `lastOpenOutcome` tells the console whether to say "blocked".
- **Pacing counts from `startIndex`** (where the talk began, stored in the saved session; Reset restarts it from the current slide), so starting mid-deck does not read as "ahead". Budgets are max(words / 150 wpm, 30 s); on time is within 30 s. **Keys** (`keys.ts`): Enter and Space on a focused button are left to the browser (`leavesKeyToBrowser`), so every console button refuses focus on a mouse press (`onMouseDown` preventDefault; the target field must take focus), else a clicked Pause eats the next Space; keys typed in a field or with Ctrl/Meta/Alt are ignored; while black, Next/Prev only bring the slide back. **Escape must be pressed twice within 2 s to end** (`confirmsExit`; a clicker's one button alternates F5/Esc, so one Esc would close the projector mid-lesson): the first shows a "Press Esc again" notice. End presentation navigates with `replace`, so Back never returns to a dead console.
- **Untested in a browser**: two real windows, `BroadcastChannel` delivery, pop-up blocking, full screen on a projector, a clicker. Tested: the reducer, key map, pacing, timer, protocol, session and the two views' render states.

## Theme system (the main styling gotcha)

`src/index.css` defines two parallel CSS-variable namespaces bridged into Tailwind v4 via `@theme inline` (no `tailwind.config.*`).

- **`app-*`** (`--app-background`, `--app-accent`, …): all editor/app chrome (`bg-app-*`, `rounded-app-*`) — never changes with a deck's theme. Light and dark are **separate purpose-built palettes** (dark is near-neutral black, not the darkened light palette, which read visibly purple). `--app-accent-text`/`--app-highlight-text` are AA-safe as text on the page background; `--app-highlight-foreground` is dark ink for text on a solid highlight fill. `--app-accent`/`--app-highlight` are for fills.
- **App light/dark** (`lib/appTheme.ts`, zustand, applied at module load): `mode` (`'system'|'light'|'dark'`, the setting, stored as a real value) vs `theme` (`'light'|'dark'`, what it resolves to). Paint code reads `theme`; only the settings modal reads `mode`. The OS `change` listener keys off `mode === 'system'`. `[data-theme='dark']` overrides only `app-*`; `dark:` is rebound to that attribute via `@custom-variant`. `ThemeToggle` (two-state, commits to the rendered side) is for `/login`. **`AuthVisualPanel` and dashboard `AppSidebar` are deliberately always-dark** (use `ThemeToggle`'s `onDark` prop there).
- **`slide-*`** (`--slide-background`, `--slide-accent`, `--radius-slide`, …): the deck's theme, applied only inside a scoped `ThemeProvider` (`display: contents` div, `applyTheme(theme, ref)` from `lib/theme-tokens.ts`), never on `<html>`. `layouts/*` use `slide-*` exclusively; `components/ui/*` use `app-*` exclusively. `ThemeProvider` is instantiated around `CardCanvas`, sidebar thumbnails, `PresentPage`, and each `ThemePanel` preview (it also provides the theme as React context).
  - **`applyTheme` must stay in `useLayoutEffect`** — a passive effect paints one frame with `:root` fallbacks (a flash of the wrong palette on every mount).
  - **Read the slide fonts as `var(--slide-font-heading)` / `var(--slide-font-body)` (`SLIDE_HEADING_FONT`/`SLIDE_BODY_FONT` in `theme-tokens.ts`), never via a `--font-slide-*` alias**: an `@theme inline` alias is substituted once on `:root` and blinds every scoped override (theme fonts and toolbar picks never reached slides). A test fails if a component uses the alias. **Every element carrying words sets one of the two fonts on its own root** (the node `Adjustable` overrides), else it inherits the chrome font.
- `BUILTIN_THEMES` is the only source (no custom themes). Thirteen presets. Three warm ones come first: Bordo (`bordo`, Bricolage Grotesque + Hanken Grotesk), Peacock (`peacock`, Source Serif 4 + Hanken Grotesk) and Forest (`forest`, Hanken Grotesk throughout), each a cream or sand page with a deep ground, glow only and no stars (a test pins both). **`DEFAULT_THEME` is found by id as `bordo`**, so the order of the list can change without moving it, and the `:root` slide block in `index.css` mirrors Bordo. Every theme's `colors` also hold `deep` (the ground a title slide is drawn on), `deepForeground` (its ink) and `tint` (the ground of a quote or stat hero); `applyTheme` writes them as `--slide-ground-deep`, `--slide-ground-deep-foreground`, `--slide-ground-deep-muted` and `--slide-ground-tint`, the third derived by `deepMuted(colors)` (`mixHex` of the ink toward the ground at `DEEP_MUTED_WEIGHT`, so no theme stores it), and no ground, ink, surface or accent-foreground is pure white or black (pinned by a test). Then five celestial: Moonlight, Cosmic Observatory, Deep Space, Solar Flare, Aurora — **ids stay `minimal/editorial/midnight/bold/sage`** (deck rows key on them). Then five that are not: Paper (`paper`, ruled page, Source Serif 4), Chalkboard (`chalk`, Caveat headings only + Atkinson Hyperlegible body, chalk-dust stars), Blueprint (`blueprint`, JetBrains Mono + Atkinson, `grid` plus heavier glow lines every 120px), Pop (`pop`, Bricolage Grotesque, two hard-edged corner blocks) and Boardroom (`boardroom`, Hanken Grotesk, a faint top rule). New ids are additive. **Their fonts are web fonts**, imported in `main.tsx` from Fontsource (separate woff2 assets, fetched when a slide uses one). A stack names the real family first and Fontsource's `<Family> Variable` alias second (`'Source Serif 4', 'Source Serif 4 Variable', Georgia, serif`) because the PPTX export names a face by the **first** family (`faceName`) and PowerPoint has no "... Variable"; a test requires every web font a new theme names to be imported by `main.tsx`. Adding a theme font = the package, the `main.tsx` import and that test's table. Decks store the whole theme as JSON, so `loadDeck` runs it through `resolveTheme(stored)` (match on `id`) so old decks pick up redesigns and never lack `celestial`/`accentSoft`. `ThemePanel` is preset-only. `darken()` derives `--slide-canvas-background` (and `--app-canvas`).
- **Celestial backdrops** (`lib/celestial.ts`, `components/theme/SlideBackdrop.tsx`): each theme has a `celestial` field as CSS/SVG layers, never images. `applyTheme` writes only the glow (`--slide-backdrop-image`); `SlideBackdrop` reads the theme from `SlideThemeContext` (`slideThemeContext.ts`, separate file for fast refresh). Each space theme uses two or three decoration kinds, never all (`theme-tokens.test.ts`); no theme uses all five. The newer five say what they are mostly in `glow` layers, including `linear-gradient`/`repeating-linear-gradient` rules (paper lines, blueprint heavy grid, boardroom top rule) that **the PPTX backdrop does not draw** (`export/backdrop/glow.ts` reads only `radial-gradient(W% H% at X% Y%, rgba %, rgba %)` and drops the rest, so a ruled line is screen-only there; a hard edge such as Pop's blocks is two radial stops two points apart, which does export). Positions are % of the card, radii px (`circle <r>px`; orbits/bodies use `aspect-ratio: 1`; constellation SVG `preserveAspectRatio="none"` + `vector-effect="non-scaling-stroke"`). A star field is **one** element (`starFieldCss` composes N radial-gradients). The sky is **seeded on the theme id** (deterministic across renders/thumbnails/preview — `Math.random()` would reshuffle). `starPositions` is shared with the PPTX export; **its `rand()` draw order is load-bearing** (a star rejected by `avoidCenter` consumes exactly its x and y draws). `avoidCenter` keeps stars off the heading band; every palette's pairings are AA-checked.
- `components/theme/SlideSurface.tsx` is the shared card chrome (surface + backdrop + content, `isolate`, the 16:9 floor with `overflow-clip`, and the card's `ground`, see Grounds); `CardCanvas`, `PresentPage` and the thumbnails all route through it. `ThemeGrid` tiles are not: they are plain SVG wireframes.

- **Outline thumbnails** are the real `LayoutRenderer` at 800×450 scaled with `transform: scale()`. ## Narration tab (`components/editor/NarrationTab.tsx`, `engine/narration.ts`, `ai/narrationPrompt.ts`)

The **Narration** tab beside **Design** in the editor's right panel: the per-slide spoken script for a cloned voice. (It replaced the `/deck/:id/narrate` page, which now redirects to the editor.) Most decks arrive already narrated (from `speakerNotes`); the tab's own call fills blanks or regenerates chosen slides. Design: `docs/superpowers/specs/2026-09-26-narration-tab-design.md` (data rules: `2026-09-02-narration-page-design.md`).

- **The tab writes for the slide the editor is on**: `selectedCardId ?? activeCardId` (the pen's rule), no stepper — the canvas is the viewer. `ToolsPanel` takes the tab as a `narrationTab` slot and keeps it mounted while hidden. **Writing scripts is a background job** (`jobs/narrationJob.ts`, kind `narration`, see Background jobs), so leaving the editor (Present, Back) or switching tabs no longer cancels it; the tab starts it, shows it while it runs on this deck (Cancel, then Try again / Dismiss on failure) and dismisses it once done. **The job targets card ids, read into positions at the start of each run** (so Try again after a reorder writes the slides chosen), and applies nothing if `sameSlides` says the slides changed before the reply landed. On the open deck it applies through `applyGeneratedNarration` (one undo step); once the user has left that deck it writes through `insertNarration` (write-only, only the changed cards, like `insertGeneratedDeck`). The two Generate buttons are now one AI icon that opens the slide picker (the single-slide confirm is gone; the picker asks before overwriting).
- **`narration` is `{text, generated}`**; `narrationStatus`, `isRegenerable`, `isResettable` are derived, so nothing falls out of sync, and keeping `generated` makes "Reset to generated" literal. A blank script reads `empty` even if a generated copy survives (Reset stays offered).
- **`mergeNarration` writes only to slides the user selected**, whatever the model returned (pure, tested — the feature's core invariant). `isRegenerable` only decides which boxes start ticked. A generation is one call over an explicit set (single slide or ticked boxes in `GenerateScriptsModal`); the set drives both `narrationSlides` (unselected marked `SKIP`, still sent as context) and `mergeNarration`. Replacing hand-written words asks twice, on **both** routes (`ConfirmReplaceModal`). `generateNarration` goes through `FallbackProvider` (same capacity-only failover, retry, abort).
- **`narrationMaxTokens` is bounded both ways**: floor 5200 (gpt-oss-120b spends ~3,400 reasoning tokens; below that you get an empty completion and a 400 `json_validate_failed`, not a shorter script); ceiling 7000 (Groq counts *requested* output against its 8,000 TPM window; 8192 is refused outright). One script ≈ 141 tokens → ~20–25 slides max. **Above that it fails as a 400 (`request` kind), which does not fail over to Gemini.** The 10-slide cap keeps decks well under it.
- Typing debounces at 500ms and coalesces undo on `narration:<cardId>`; Reset and whole generations write immediately. The editor's own unmount and `beforeunload` flush already covers a typed script. The panel surfaces `store.status === 'error'` (a silent failed save of hand-typed text is the worst outcome; also how a missing migration 0008 announces itself). Accepted limitation: the brief (audience/tone) isn't stored on the deck, so narration infers tone from deck text.

## Voice (`src/voice/`, `components/voice/CloneVoiceModal.tsx`)

The Narration tab's footer has an **AI icon** (bottom left; opens the slide picker, `GenerateScriptsModal`, which asks before overwriting hand-edited scripts) and **Voice & video** (bottom right; opens `CloneVoiceModal`, titled *Narrated video*; the Create & export menu's Narrated video item opens the same dialog). The modal sets up a **Cartesia** voice: pick a premade voice or record and clone your own (with a passage to read aloud), tune language, speed (0.6–1.5), volume (0.5–2.0) and emotion, and **Preview** two fixed sentences. Recording sits under a **Before you record** notice (the clip goes to Cartesia; the copy stays in the site's Cartesia account until deleted in the dialog or with the account; only you can pick it in the app, the site's operator can see it in Cartesia) and Record stays off until **This is my own voice, and I agree to it being copied** is ticked (`canRecord`'s `consented`). The saved voice feeds the preview **and the narrated video** (see Narrated video); nothing else plays or exports audio. The modal's bottom button is **Generate video** (not "Generate Presentation": that is what makes a deck at `/new`): it saves the voice, starts the video as a background job (`startVideoJob`) and closes the modal; the editor stays open and the corner panel shows progress, as for a quiz. It is disabled while a video job runs. Design: `docs/superpowers/specs/2026-09-27-narration-voice-design.md`.

- **All network calls are in `voice/cartesia.ts`** (`listVoices`, `cloneVoice`, `speak`); everything else is pure or UI. The key is `VITE_CARTESIA_API_KEY`, **baked into the client bundle by decision**: cloning and listing voices need a full API key (Cartesia's browser tokens only cover speech), and Cartesia itself says never to ship one in a client app, so **a deployed build lets anyone who loads it spend on the account and list or delete its voices**. Same class of risk as the Anthropic key, worse in scope. A server proxy would replace only this file. The key goes out as `Authorization: Bearer` because that is the only credential header the API's CORS policy allows (`Authorization, Cartesia-Version, Content-Type`). **Untested live**: the `Bearer` form (a few of Cartesia's curl samples omit it) and the `voice` field as a bare id string in `/tts/bytes`; a valid key that gets 401, or a speech request rejected for its voice field, is a one-line change in that file.
- **Every call honours the `AbortSignal`, and an abort stays an `AbortError`** (never a `CartesiaError`), so closing the modal cancels quietly. No retry: each is a single user action with a button to press again.
- **Emotion is English-only** in Cartesia; `speakBody` sends none for another language and the modal disables the select. Six languages ship (`voice/scripts.ts`: en, es, fr, de, pt, it), because the reading script and preview sentences must be in the voice's language; adding one is a row in each table plus `VOICE_LANGUAGES`. Only the first 100 voices are listed (search narrows).
- **The microphone is always released** (`voice/recorder.ts`): stop, cancel, the 15 s limit and errors all stop every track, and the modal's unmount cleanup cancels a recording, aborts requests and stops the preview, because Escape/backdrop/Cancel run no code of ours. A browser that can only record mp4 (Safari) is reported as unable (Cartesia accepts webm/ogg, not mp4). A clip needs at least 3 s and a name of at most 60 characters (`canClone`). `recorder.test.ts` fakes `navigator.mediaDevices` and `MediaRecorder` to pin the release.
- **Recorded voices have owners (`voice/clonedVoices.ts`, pure, tested; migration 0017).** Every user shares the site's one Cartesia account, so Cartesia's `is_owner=true` list is **everybody's** clones; before 0017 "Your voices" showed every user's recorded voice to every other. Now: cloning records the owner (`cloneOwnVoice`; a voice that can't be recorded is deleted from Cartesia again, and a clone that finished as the dialog closed is still recorded), "Your voices" is `ownClones` of that list, a saved cloned pick not known to be the user's is dropped (`keepOwnVoice`), and recording needs ownership to be known (`canRecord`'s `ownVoicesKnown`). **All of it fails closed**: unknown owner (no table, failed read, cloned before 0017) = shown to and used by nobody. *Delete this voice* (under the list, for a selected own voice) deletes from Cartesia, then the row (`deleteOwnVoice`; a Cartesia failure keeps the row). `authStore.deleteAccount` deletes all the user's voices from Cartesia **before** `delete_own_account()` and stops with nothing deleted if any fails (`deleteAllOwnVoices`; skipped without a key or without 0017). The key in the bundle still lets someone technical list every voice from Cartesia directly; only a server proxy closes that.
- **Saved per user in `voice_settings` (migration 0014, owner-only RLS)**, deliberately not on `profiles` (whose `profiles_select` lets a teacher read their students' profiles). It stores which voice was picked and its settings; the voice itself lives in the site's Cartesia account (see above). `voiceStore` loads on modal open, is **cleared when the signed-in user changes** (a load in flight across the switch is discarded), and **does not gate anything**: a project without 0014 works, the voice lasts for the session, and the modal says to run the migration. `supabase/tests/0014_voice_rls.sql` is hand-run; last run 2026-09-27, all checks passed.
- **Not testable here (no jsdom, microphone or key), checked by hand:** recording, playback, the live Cartesia calls, the microphone indicator going off on close. Tested: request building, response parsing, error mapping and abort (`cartesia.test.ts` against mocked `fetch`), settings mapping, the recorder's release, the store, voice ownership and deletion (`clonedVoices.test.ts`, mutation-checked: unknown owner shows nothing, an unrecordable clone is deleted again, Cartesia before the row, a failed voice delete stops the account delete), and the modal's and tab's render states (including the notice before Record and the unticked consent box). **SSR quirk for tests:** zustand server rendering reads a hook's *initial* state, so `store.setState` cannot set what a component reads through a hook; only what it takes with `getState()` (the modal's draft and loaded flag) is settable in a render test.

## Narrated video (`src/video/`)

**Generate video** (the video dialog's primary button; it saves the voice, then starts a background job, see Background jobs) narrates every slide, draws the slides, and stitches them into one video in the browser, saved to the private `deck-videos` bucket: **one video per deck, replaced each time**, played and downloaded from the modal (progress and Cancel are in the corner panel, not the modal). Design: `docs/superpowers/specs/2026-09-27-narrated-video-design.md`. A video is a **separate artifact generated from a deck on demand**: it never reads-then-writes `cards` and is **not precedent for a "regenerate this slide" button** (same carve-out as narration and quizzes).

- **Pure rules are tested; browser code is not.** `timeline.ts`, `format.ts`, `paths.ts`, `videoRecord.ts`, `storageErrors.ts`, `ui.ts`, `storage.ts` (against `StoragePorts`) and `pipeline.ts` (generic over injected `narrate`/`silence`/`drawSlide`/`encoder`/`save`) have colocated tests. `narrate.ts`, `encode.ts`, `renderFrame.tsx` and `generate.ts` use `OfflineAudioContext`, WebCodecs, the DOM and `html-to-image` and are checked by hand; keep them thin. The modal's render tests set the saved-voice-known flag on `useVoiceStore.getInitialState()` (the SSR quirk from Voice: the modal reads `loaded` through a hook, and server rendering reads the store's initial state).
- **Lazy.** `mediabunny` and `html-to-image` are only reached through `import('@/video/generate')` (which imports `encode`, `narrate`, `renderFrame`); the entry bundle must not contain them. Check the build's chunk list after touching imports.
- **Slides.** Each slide is 1280x720 (`FRAME_WIDTH`/`FRAME_HEIGHT`), drawn by the `SlidePreview` composition (`renderFrame.tsx`, off-screen) and **scaled to fit, never cropped**, when taller than the frame (`fitScale`). A blank script is shown silently for 4 s (`SILENT_SLIDE_SECONDS`). Hold time is each clip's own `duration`, and the audio and video timelines are built from the same numbers, so a zero-length clip is refused (`MIN_NARRATION_SECONDS`) rather than allowed to desync the rest.
- **The tab must be visible while slides are drawn**: html-to-image resolves its image creation inside `requestAnimationFrame` (paused in a background tab) and the settle wait is a `setTimeout` (throttled there), so `renderFrame` waits for `visibilitychange` (`whenVisible`). It is not `SlideBody`: that measures `clientWidth` synchronously in a `useLayoutEffect`, so nudges and ink do not depend on its `ResizeObserver` for the first render. **Theme web fonts are embedded**: html-to-image draws through an SVG `foreignObject` that cannot see the page's `@font-face`, so `createSlideRenderer` builds `fontEmbedCSS` once per video (`getFontEmbedCSS` on a probe holding the theme's heading and body fonts, not on the first slide, which may use only one of them) and passes it to every frame. Toolbar fonts (`FONT_CHOICES`) are system fonts and need none; **a web font added to the toolbar must join the probe**, or the video silently uses a fallback. An `image` block from a host without CORS headers will be missing from the frame.
- **Format**: MP4 (`avc` + `aac`) preferred, WebM (`vp9` + `opus`) fallback; `hasWebCodecs()` (sync) disables the button, `detectFormat()` (in `encode.ts`) runs before any Cartesia request so a browser that cannot encode never spends credits.
- **Save order is the safety rule** (`saveVideo`): upload (upsert), then write `presentations.video`, then remove the previous object if its path differs (MP4 -> WebM). A record-write failure removes a *new* object but never the previous one. Cancelling before the upload writes nothing. **The storage client's `upload` takes no `AbortSignal`, so the start of the upload is the point of no return**: the job is then `cancellable: false`.
- **Videos page** (`/videos`, `pages/VideosPage.tsx`, `components/videos/`): every deck with a video, newest video first, as badge cards (the deck's first slide as cover, a play disc, the running time). Read-only: making and replacing stay in the deck's dialog, and a video goes with its deck. One read (`listVideoDecks` in `presentationStore.ts`, sharing `fetchCovers` with `listDecks`); which rows count, the order and the search are `video/library.ts` (pure, tested). Links are signed only when a video is played (`signVideo` in `storage.ts`, which `loadVideo` also uses), not per card. Playing clears the card's new-video dot. A failed read (e.g. no 0015) shows Try again, not a migration name.
- **The dialog** (`CloneVoiceModal`) is three numbered steps: 1 Voice (tabs *Pick a voice* / *Record your voice*; both panels stay mounted with `hidden`, so a recording in progress survives a switch and render tests still see the consent notice before Record), 2 Settings (with Preview), 3 Video (the current video, or "No video yet"). Everything about Generate (an error, else why it is off, else a run in progress, then the credits note) is one footer that stays at the bottom of the dialog while it scrolls.
- **Deleting a deck** deletes the row, then its video (`deleteDeckWithVideo`): the record is read first, the file removed only once the row is gone, so a failed delete keeps the video and throws to `DeleteDeckModal` (which says nothing was removed and offers Try again). Reading/removing the video is best effort and never blocks the delete. **`delete_own_account()` does not remove videos**: they are orphaned (recorded voices are deleted by the app before the RPC; see Voice).
- **Not testable here, checked by hand**: the real encode, DOM-to-canvas fidelity (themes, backdrops, ink, nudges, tall cards), playback, the upload, and RLS (`supabase/tests/0015_video_rls.sql` is hand-run and passed on 2026-09-27).

## Background jobs (`src/jobs/`, `components/jobs/`)

The four long generations (deck, quiz, video, narration scripts) run as jobs that outlive the page that started them. Spec: `docs/superpowers/specs/2026-10-02-background-generation-design.md`. They are the same carve-out as before: separate artifacts or the one creation call, **never a rewrite of `cards`**.

- **One job per kind** (`deck`/`quiz`/`video`/`narration`) in `jobsStore` (zustand, module level); `start(spec)` returns `false` while that kind runs (no queue; start buttons are disabled with the reason). Callers use `jobs/start.ts` (`startDeckJob`/`startQuizJob`/`startVideoJob`/`startNarrationJob`), the only place real dependencies are wired. `deckJob`/`quizJob`/`videoJob` build a `JobSpec` from an input plus **injected deps**, so they are tested against fakes; a spec's `run({signal, report})` resolves `{deckId}` and rejects on failure or cancel. Timelines (`timelines.ts`, pure) map pipeline/quiz/video stages onto the panel's rows.
- **Every write goes through the run-id check** (`current()` in `execute`: the run's id is still its kind's and its signal is not aborted), so cancel, replace and reset settle into nothing: no deck, quiz or video after Cancel. Controllers live in a module `Map`, not state. `retry` re-launches the kept spec (a quiz spec's closure keeps the finished tests, so it resumes at the failed one). `abortForDeck` runs from the dashboard's delete confirm (`HomePage.tsx`) before `deleteDeck`; `reset()` runs when the auth user id changes (sign-out included), so one account's result never lands in the next. One `beforeunload` listener warns while any job runs: **jobs live in this tab, a reload ends them**, nothing resumes. The video still needs the tab visible while slides are drawn.
- **A background job must never call `createDeckFromGeneration`**: its last `set` replaces the editor's open deck. The deck job uses `insertGeneratedDeck` (write-only). It also refuses to insert if the signal aborted while the pipeline resolved, and deletes the brief draft only after the insert (so a failed job's "Edit brief" `/new?draft=<id>` still has it).
- **The deck job's photo stage** (`DeckJobDeps.addPhotos`, timeline row `photos`, progress 0.88, between repair and save) is cancellable: an abort (signal or `AbortError`) inserts nothing and settles cancelled; any other failure inserts the deck without photos. `jobs/start.ts` always wires it.
- **Non-cancellable points** report `cancellable: false`: the deck insert, `create_quiz`, the video upload (`canCancelVideo`). `cancel` is a no-op on a running job without it; the × is disabled.
- **`newItems.ts`** marks a deck's unseen result (`markNew` on `done`, from the store) for the card's yellow dot (`NewDot`; `DeckCard`/`DeckListRow` read `useNewItems`). `localStorage` `lekturac:new-items:<uid>`, **user-namespaced with no un-namespaced fallback**, null key while the session hydrates (the `briefDrafts` rules; snapshot cached and rebuilt only on mutation/`storage`). Cleared per kind when the user opens the thing: `/deck/:id` clears `deck`, the quiz modal's list tab `quiz`, the voice modal showing a saved video `video`; the same delete confirm clears all (`clearDeck`).
- **`JobTray`** is mounted beside `<Routes>` in `App.tsx` (signed-in only, bottom right; running timeline, done -> View button, failed -> Try again / Edit brief). On `/deck/:id` rows collapse to pills, and **that deck's narration job is hidden** there (the Narration tab shows it; its View is `?narrate=1`, and it marks no new dot), as is **that deck's quiz job**: `QuizJobStrip` (top bar, between save status and zoom) shows it, and the Create & export trigger, its Quiz item and the list tab carry the new-quiz highlight until the list is opened. A done video row stays until viewed or dismissed, like the others (it used to fade after ~6 s, which was missed). View targets `/deck/:id?quiz=list` and `?video=1` are read **once** by `EditorPage` (opens the quiz list tab / the voice modal) and removed. `HomePage` reloads its list when the deck job is `done`.
- **`src/jobs/*` reaches `@/video/generate` only through `import()`** (`start.ts`; `videoJob.ts` imports types only), so the encoder stays out of the entry bundle.
- Not testable here: the animations, a real job surviving navigation, tab-visibility waiting, the reload warning (by hand).

## Quizzes (`src/quiz/`, `components/quiz/`, `pages/QuizPage.tsx`)

The Create & export menu's **Quiz…** item (`QuizModal`) turns a deck into a quiz: a quiz is **1–3 tests** (`MAX_QUIZ_SECTIONS`), each with its own type — multiple choice (A–C/A–D), fill in the blank (optional word box), true/false (`TRUE/FALSE` or `T/F`) — 1–20 items (`MAX_QUIZ_ITEMS`, per test), and an editable title and instructions (spec `2026-10-01-quiz-test-sections-design.md`). The modal is wide with two tabs, Create new quiz and Quizzes from this deck (Generate starts a background job and closes the modal; the result is reached from the Quizzes tab, the top-bar strip or the corner panel). Design: `docs/superpowers/specs/2026-09-24-quiz-generator-design.md`. A quiz is a **separate artifact generated from a deck on demand**; it never reads or writes `cards` and is **not precedent for a "regenerate this slide" button** (same carve-out as narration, see "Core rule: generate once"). No regenerate-in-place either: a new quiz is a new generation.

- **One model call per test, in order** (`quiz/sections.ts` `generateSections`, pure, tested): each later call is told the prompts already asked (`avoidList`, capped at 40 prompts / 2,000 characters for Groq's window). A failed test keeps the tests before it (held in the job spec's closure, `jobs/quizJob.ts`) and **Try again resumes at the failed one**; a new Generate is a new spec, so it starts fresh; cancel drops them silently. A test with zero valid questions is a failure of that test (`EmptySectionError`). The whole quiz is saved in **one** `create_quiz` call. Three calls back to back can meet a saturated TPM window; the shared retry absorbs it, so a 3-test quiz can take over a minute.
- **Tests are stored inside the quiz**: `settings.sections` (title, instructions, type, sub-option) and per-question `section_index`/`question_type`. `fromDbSections` reads a pre-0016 quiz as one test titled "Test 1" with its type's default instructions; every reader groups with `groupBySection` (`quiz/rows.ts`) and **numbering restarts in each test** (preview, PDF sheet and key, taking page, result review — whose right/wrong marks are looked up by global position). The form is a pure reducer (`quiz/sectionForm.ts`): default titles follow position until typed, instructions follow the type until edited, a blank title saves as the default.
- **Free chain only.** `QUIZ_CHAIN` (`fallbackProvider.ts`) is `GroqProvider` on `openai/gpt-oss-120b`, then `groq/compound` — never Anthropic (billed) or Gemini. Empty without `VITE_GROQ_API_KEY`; the Quiz button is then disabled (`QuizProvider` in `ai/provider.ts` is deliberately not on `AIProvider`, so the other providers need no stubs). It shares `runWithFailover(chain, label, call, signal)` with `FallbackProvider` (the class delegates to it), so **capacity-only failover and cancel-never-hands-off are one code path**; `generateQuizWithFallback` is the entry point and `quizFallback.test.ts` mutation-checks that an `auth` failure does not fail over.
- **Budget** (`ai/quizPrompt.ts`): `quizMaxTokens(n) = clamp(n*110 + 3800, 5200, 7000)` (the 5,200 floor clears `gpt-oss-120b`'s ~3,400 reasoning tokens, 7,000 is Groq's ceiling; same reasoning as `narrationMaxTokens`). The deck text sent is capped at **600 characters per slide and ~6,000 in total** (`MAX_SLIDE_CHARS`/`MAX_TOTAL_CHARS`; every heading kept, body lines shared out of the total) because Groq's ~8,000 TPM window counts input **plus requested output**. 20 items on a very large deck is the tight case: a 429 there fails over to `groq/compound`, and if both are out the user sees "busy, try again". Later tests also carry an ALREADY ASKED list (`avoidList`, ≤40 prompts / 2,000 chars), so a 20-item test on a very large deck can exceed the window; that request then fails over (capacity) to `groq/compound`. Raising any cap means revisiting this.
- **The model is not trusted for structure** (`quiz/build.ts` `buildQuestions`, pure): drops questions citing an out-of-range slide (a false citation is worse than a missing question) or whose shape doesn't match the type; trims to `count`; reports a **shortfall** rather than repairing with a second call; **shuffles multiple-choice choices client-side** with a seeded shuffle (models bias the answer position; the seed makes it testable), carrying the correct index with them. Replies go through zod (`quiz/schema.ts`) with one retry that sends the exact errors. The `wordBox` flag is stored in `settings`; only the word list is derived at read time. A blank answer with no letter or digit (and any such accepted alternate) is dropped, since the server could never match it.
- **Storage (migration 0012 REQUIRED).** `quizzes` gains `code` (8 characters, the alphabet of `generate_join_code()`; `quiz/quizCode.ts` **must stay in step with `generate_quiz_code()`**, `quizCode.test.ts` checks it), `quiz_type` and `settings` (presentation only; scoring ignores it). `quiz_questions` stays **owner-only under RLS** — that is what makes the answer key and PDF owner-only *by data*. Students touch a quiz only through `get_quiz_for_taking` (never returns answers) and `submit_quiz_attempt` (**scores on the server**; one attempt per student per class; returns which were right, not the answers). `create_quiz` is `security invoker` (RLS decides who may save) and atomic. It **does not use `INSERT … RETURNING`**: it generates the id and code up front, because under invoker RLS `RETURNING` re-checks the SELECT policy `can_read_quiz`, which looks the row up in the table and cannot see it yet, so the insert would be refused. Don't "simplify" it back. That rationale is reasoned from the SQL, not observed: the hand-run test shows the version without `RETURNING` saves a quiz, not that one with it would be refused. `supabase/tests/0012_quiz_rls.sql` passed on 2026-11-06 (after 0018). `create_quiz` also stores `choices` only for multiple-choice quizzes, and `normalize_answer` strips punctuation via `[[:punct:]]` (never letters, whatever the database locale; case folding of non-ASCII letters is locale dependent). `assert_quiz_question` guards the `create_quiz` path only (the 0009 `quiz_questions_owner_all` policy lets an owner write their own questions directly). The word-box flag is read as a JSON boolean (`settings->'wordBox' = 'true'::jsonb`, not a cast: `settings` is client-supplied and a bad value must not break taking). **0016 replaced `create_quiz` with the `p_sections` version** (1–3 tests, 1–20 questions each, `settings.sections`, per-question `section_index`/`question_type`); scoring is now per `question_type`, and `get_quiz_for_taking` returns `word_boxes` per test. The no-`INSERT … RETURNING` rationale above applies to 0016's version too.
- **0012 also gates the teacher classroom pages' reads.** `QUIZ_COLUMNS` (`classroom/rows.ts`) now selects `code` and `quiz_type`, so on a database without 0012 the Classes / Students / Quizzes loads **error** (same shape as 0006/0008 gating every card write); the student loader (`loadStudentClassroom`, behind My classes and the class page) selects `STUDENT_QUIZ_COLUMNS` (`code`, `quiz_type`) too, so it errors the same way. Saving a generated quiz on a database without 0016 fails with "Run migration 0016 in Supabase." (the model call succeeds; `create_quiz` is what fails; the message names 0016 because 0016 replaced `create_quiz`).
- **Rules.** Any deck owner can generate; only **Teachers** see a code and can post (a General account has no classes and account type is permanent; the modal says "Sharing needs a Teacher account"). A non-member with a code is **refused** ("join the class first") — a code never auto-joins a class. Posting is never at generation time: it is from the Quizzes page (`QuizRow`: a class picker plus an explicit Post button, never on change; unpost chips; copy code/link), and the same rows appear in the class folder. While taking, answers are kept in `localStorage` (`lekturac:quiz-answers:<uid>:<quizId>`, `quiz/taking.ts`; the `briefDrafts` rules: user-namespaced, no fallback, null key while hydrating), restored only where they still fit the question, and cleared on submit or on the one-attempt refusal (`isAlreadySubmitted`, which matches 0016's wording). Submit with gaps marks them and jumps to the first; a confirm names the class. No slide numbers on the student's questions or result review (students can't open the deck). True/False is a `role="radio"` group with one Tab stop and arrow keys (`lib/radioKeys.ts`, tested). The result review shows the student's own answer beside each ✓/✕ (`answerText`), never the correct one; the server keeps only the score (`quiz_attempts` has no answers), so the review lasts only while the page is open, and the page says so. Students arrive at `/quiz/:code` by link, by the "Have a quiz code?" field on `MyClassesPage`, or from the **Quizzes panel on `StudentClassPage`** (`studentClassQuizzes` in `classroom/select.ts`: newest posting first; **Take quiz**, or "Submitted · score" once they have an attempt *for that class*). It reads only what RLS lets a member see (`quizzes`, `quiz_classes`, their own `quiz_attempts`) and shows no question count — `quiz_questions` is owner-only, so a student's embed of it is always empty (hence `STUDENT_QUIZ_COLUMNS`, unlike the teacher's `QUIZ_COLUMNS`). `classroom/stats.ts` is unchanged: a submitted attempt flows into the existing dashboard numbers.
- **Deleting.** The owner deletes a quiz from the deck's "Quizzes from this deck" list or the teacher's `QuizRow` (Quizzes page and class folder). Both go through `DeleteQuizConfirm`, which first reads `quizUsage` (class postings and attempts, readable under RLS because a quiz is only ever posted to classes its owner teaches) and names what is lost (`quiz/deleteMessage.ts`, pure, tested); Delete waits for that count. `deleteQuiz` is a plain row delete under the 0009 `quizzes_delete` policy (no migration): questions, postings and **every attempt** cascade, so those scores leave the class statistics for good. A refused delete (0 rows) is an error via `changed`.
- **PDF** (`quiz/pdf/`) is **owner-only by data**: the button exists only where answers were loaded through the owner's own `quiz_questions` read (`loadOwnerQuiz`), and a student session has none to print. `jspdf` is `import()`ed at export time (own lazy chunk, never in the entry bundle); Noto Sans regular/bold are fetched from `/fonts` (`public/fonts`, OFL) because jsPDF's built-ins are Latin-1 only, falling back to Helvetica with a warning (also when the fetched file isn't a TrueType/OpenType font or jsPDF can't register it). Latin, Greek and Cyrillic only — no CJK or Arabic. The word box is drawn inside a border, and the sheet never ends on a spacer (which could open an empty page before the key). Layout (`quizPdfLayout.ts`) is pure; `quizPdf.ts` only draws.
- **Testing**: pure Vitest only — prompt and budget clamp (`quizPrompt.test.ts`), schema and `buildQuestions` (`schema.test.ts`, `build.test.ts`), the Groq call and failover against mocked `fetch` (`groqQuiz.test.ts`, `quizFallback.test.ts`), row mapping (`rows.test.ts`), taking logic (`taking.test.ts`), code (`quizCode.test.ts`), PDF layout (`quizPdfLayout.test.ts`), sections (`quiz/types.test.ts`, `quiz/sections.test.ts`, `quiz/sectionForm.test.ts`) and the modal's render states (`components/quiz/QuizModal.test.tsx`). `QuizPage`, `QuizPage` and PDF drawing are not exercised in a browser. **`supabase/tests/0012_quiz_rls.sql` is hand-run** (like 0009/0010: students can't read `quiz_questions`, the RPC refusals, server-side scoring per type, one attempt, a General account can create but not post); last run 2026-11-06, after 0018, all checks passed; `supabase/tests/0016_quiz_sections.sql` is hand-run and passed on 2026-11-06.

## Lessons (`src/lesson/`, `components/lesson/`, `pages/LessonPage.tsx`)

A **lesson** is a quiz watched as the deck's narrated video: it pauses at each question's slide and the student answers before it goes on. It is a `quiz_classes` posting with `mode='lesson'`, not a new artifact; the teacher picks **Post as quiz / Post as lesson** (`PostModeChoice`) beside the class picker on `QuizRow`, sees posted lessons as a **Lesson** chip, and the chip opens `LessonProgressModal` (a student's Not started / In progress / Finished with the score, and the hardest checkpoints, from `studentProgress`/`hardestCheckpoints`; the roster and attempts come from the page's own classroom load). Students open it at `/lesson/:code/:classId` from the class page. Spec: `docs/superpowers/specs/2026-11-06-lessons-design.md`. It is **not an AI feature and not precedent for regenerating slides**: no provider call anywhere in it, and it never touches `cards` (same carve-out as quizzes and the video).

- **Readiness** (`lesson/readiness.ts`): "Post as lesson" needs the deck and a video **with slide timings**. Timings live in `VideoRecord.slides` (`video/videoRecord.ts`; one `{cardId, startSeconds, durationSeconds}` per slide, written by the video job); videos made before this have none, so the teacher must **make the video again** (`no_timings`). `QuizRow` reads the record once (`loadDeckVideo`) when the posting control is first drawn; the option is off with no reason text while loading. The server checks the same (the insert trigger refuses a lesson without timings).
- **Checkpoints**: `placeCheckpoints` (`lesson/checkpoints.ts`, TS, used by the player) and `lesson_stops` (SQL, used by the server) **must agree**. Both are checked against the same data in `lesson/fixtures.ts` (the SQL test copies it verbatim); change one and you change both and the fixture. A question with no slide, or one whose slide is gone, is asked at the end.
- **Watching is enforced by the server, not the player.** `lesson_progress.watched_until` is credit for real time: it grows by at most the real time since the last beat (heartbeat every 5 s while playing, slack 2 s), banked idle time is capped at 15 s, and it never passes the next unanswered stop. `answer_lesson_checkpoint` refuses an answer for a stop not yet reached ("Watch up to this question first.") or out of order ("Answer the questions in order."); a wrong answer still continues. Playback rate is fixed at 1x. The player's own clamp is convenience only. A "Watch up to this question first." refusal rewinds to the credited time and plays on; "Answer the questions in order." (the page's stops disagree with the server's, e.g. the video was made again mid-lesson), or the same question refused twice in a row, stops asking and shows `ReloadPrompt` (the server's sentence and Try again, which reloads the lesson and restarts the session): `refusalAction` in `lesson/playerUi.ts`. `loadLessonAnswers` throws (the progress modal shows its Retry) rather than reading as "Not started"; posting as a lesson without 0018 reads "Run migration 0018 in Supabase." (`quiz/postError.ts`).
- **Scoring is unchanged**: answering the last checkpoint scores the lesson and inserts an ordinary `quiz_attempts` row (same `submit_quiz_attempt` scoring per question type), so `classroom/stats.ts` and every dashboard number count lessons with no change. `lesson_answers` stores only `correct`, so progress shows hardest questions by miss rate and never an answer key; students never receive `quiz_questions.answer`.
- **Mode is fixed** per quiz and class once anyone has *answered*, not merely opened: the insert trigger refuses a quiz posting while that quiz and class have any `lesson_answers` ("Students already started this as a lesson in that class."), and a lesson posting while a `quiz_attempts` row exists whose student has no `lesson_answers` (a plain quiz attempt; "Students already took this as a quiz in that class."). A student who only opened the lesson (a `lesson_progress` row) locks nothing. The trigger's sentence appears in `QuizRow`'s error strip. To change it before that, unpost and post again.
- **Students read the video through storage**: the `can_watch_deck_video` policy on `deck-videos` lets a student in a class the deck's quiz is posted to as a lesson sign a URL (`lessonVideoUrl`, one hour); the lesson code imports only small pure modules from `src/video/` (`videoRecord.ts` and `paths.ts`) and never the encoder, renderer or storage modules, so `mediabunny`/`html-to-image` stay out of the entry bundle. A removed video reads "The video for this lesson was removed."
- Not testable here (no jsdom, no video element), checked by hand: the player, seeking blocked past a stop, resume after closing the tab, the heartbeat; `supabase/tests/0018_lessons_rls.sql` is hand-run; last run 2026-11-06, all checks passed. Tested: placement, status/progress arithmetic, row mapping, session logic, readiness and the render states above.

## Admin (`src/admin/`, `pages/AdminPage.tsx`, migration 0019)

Developer-only site-wide counts at `/admin/<section>` for a **time range** (`RangePicker`: 7 days / 30 days by day, 12 weeks by week, 12 months by month; state in `AdminPage`, shared by every section; tiles show the change vs the same length of time just before, `changeOf`: a percent against a non-zero base, "+N new" against zero, points for rates, computed from the two whole percents shown). Charts (`components/admin/AdminCharts.tsx`): `TimeChart` columns, stacked for 2+ series, with a 1/2/5 number scale (`axisTicks`), gridlines, dated labels (`labelIndices`), a legend, a hover/focus tooltip and a Show table view; series colours are `--viz-1..4` in `index.css` (validated per mode with the dataviz validator; slots 3–4 are under 3:1 on white, which is why every chart also prints its numbers). Sections (`admin/sections.ts`: People, Decks, AI quality, Classroom, Voice; one rail link each so no view is a long scroll; `/admin` and unknown sections go to People; the counts are read once and kept while switching). People: accounts, sign-ups, active users, the deck → video/quiz → class funnel; Decks: per week, slide counts; AI quality from `presentations.generation`: research outcome, flags left after repair, unsourced and hand-checked claims; classroom and voice totals. **Admin is a row in `admins`, not an account type**: no policy or grant lets the app write it, so it is granted only in the SQL editor (`insert into admins (user_id) select id from auth.users where email = …`). **An admin account is for admin work only**: `authStore.isAdmin` is read beside the profile at sign-in (`readIsAdmin`, fails closed: no table or a failed read = not admin), the rail shows only the Statistics links, and `RequireAuth` sends an admin from every page not marked `adminPage` to `/admin`. **Admins have their own login** (`/admin/login`, `AdminLoginPage`, log in only): `signIn(email, password, as)` registers the login kind before the call and `applySession` refuses the wrong kind (an admin at `/login`, anyone else at `/admin/login`) by signing straight back out *before* reporting `authenticated`, so no page sees that session; `/login` then links to the admin login. A signed-out visit to `/admin` goes to `/admin/login`. `admin_overview()` (security definer) refuses non-admins, which is what protects the data. **Counts and categories only**: the function never returns a row, name, email, title or anything typed (the brief's `objective`, sources, claim text); keep it that way. `overview.ts` (pure, tested) parses the jsonb so a missing key reads as zero. Without 0019 nobody is an admin and nothing else changes. Not yet tracked (needs a usage log): AI calls per provider, fallbacks, tokens/cost, job outcomes, feature use, save/load errors. Untested in a browser: the login refusal and redirects.

## PPTX export (`src/export/`)

`exportDeckToPptx(deck)` makes native, editable slides; nothing in `src/export/` imports React or a component (dashboard export goes through `fetchDeck`, **not** `loadDeck`). The export fits text itself (`textFit.ts`/`measureText.ts`), emits exact-point `lineSpacing` (never `lineSpacingMultiple`), and short-circuits to an `adjusted` arrangement when any element is nudged. **Photos are embedded** (`imageData.ts`, `photoPlacement.ts`): `exportDeckToPptx` fetches the pictures it can place once before drawing, in parallel with the text measurer (`prefetchDeckImages` over `placeableImageUrls`: a nudged card's images, or the lone photo of a hero/quote/standardSplit/imageFocus card; a gallery's are never fetched; browser `fetch`, 15 s timeout; only JPEG/PNG/GIF, at most 15MB, with a readable header; any failure just leaves the url out of the map) and hands renderers a `RenderContext` `{images, layout}`, so renderers stay pure and a url missing from the map keeps today's alt-text box (a failed fetch never fails the export). Placement mirrors the screen only where the arrangement has room: `hero`/`quote` with exactly one photo draw it over the whole slide (`sizing: cover`, a black scrim at 45%/40% transparency, all text forced white, credit bottom right); `standardSplit` (even `orderIndex` right, odd left) and `imageFocus` (60% left) put it in its own box beside a narrower text column; a nudged card puts it in its measured box. Every other arrangement (families, stat, twoCol) keeps the alt-text line; a hero/quote with 2+ photos omits them. **A nudged hero/quote with a lone fetched photo still draws it as the ground** (`renderAdjusted`: full slide, the same scrim, white text, credit; the photo's index is left out of the stack). **Known gap:** an explicitly named `imageFocus`/`standardSplit` card with two images draws the first on screen, but the export (`singlePhoto` needs exactly one) draws alt text. `pptxgenjs` crops `cover` against the w/h it is given, so `addPhoto` passes the picture's real aspect read from its header (`imageSize`: PNG/JPEG/GIF, first 256KB of base64; an unreadable picture is not placed, so it becomes alt text, never a stretched picture; EXIF orientation is a known gap). The credit is 8pt "Photo: name / Pexels" (pexels source only), on a dark pill when the photo is in a box; measured with the renderer's measurer and dropped if it does not fit on one line, and left off a rotated photo. It does **not** yet export `card.overlay` (hand-drawn ink); an exported deck lacks drawings until the overlay export sub-project. **Grounds** (`export/ground.ts`, pure; `groundOnSlide` in `slideRenderers.ts` reads the ground off the resolved layout in the `RenderContext`, the same one the arrangement was chosen from): a tint or deep slide (a quote, a stat hero, a title) gets its own flat `slide.background` colour, which replaces the master's backdrop picture on that slide (a flat colour adds no media part, so the one-image-in-the-master rule still holds), and its renderer is handed `groundTheme(theme, ground)`, a theme whose background, foreground, muted and accent (`groundColors`) already sit on that ground (on the deep one the accent becomes the deep ink, as on screen), so no renderer knows a ground exists; the deep ground also drops every stored text colour first (`withoutStoredColors`: card, element, run and character marks), as on screen. The `grounded` wrapper is outermost on `title`, `stat`, `quote` and `adjusted`; a plain slide's calls are unchanged, and a hero or quote with a placed photo stays plain (unchanged: the photo over the whole slide, its scrim and white text). **Read the "Implementation invariants" section of `docs/superpowers/specs/2026-09-19-pptx-fit-design.md` (and `2026-08-25-pptx-export-design.md`) before changing anything in `src/export/`.**

## Auth

`store/authStore.ts` (zustand, initialised at module load via `supabase.auth.onAuthStateChange`) exposes `user`/`profile`/`status` plus `signUp`/`signIn`/`signOut`/`resetPasswordForEmail`/`updatePassword`. `realUser()` treats `session.user.is_anonymous` as no session (leftover anonymous sessions from before accounts would otherwise skip login). `applySession()` holds `status` at `'loading'` until the profile resolves so `RequireAuth` never renders before the account type is known — **except** a token refresh for the same user with a profile already loaded, which only swaps `user` (flipping to loading would unmount the editor). An unreadable profile resolves to General (`resolveProfile`), so an un-migrated DB degrades instead of locking everyone out. `LoginPage` (`/login`) is login/signup/forgot-password in one page via local mode state; `ResetPasswordPage` (`/reset-password`) is the recovery-email landing (the Supabase client detects the session from the URL). Pre-accounts anonymous-era decks are orphaned rows, invisible under RLS.
